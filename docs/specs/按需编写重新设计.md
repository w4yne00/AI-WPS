# 按需编写重新设计

日期：2026-09-28。状态：设计已确认，代码改造已实施；真实 WPS DOC 转换及实际多模态模型验收尚未完成。

## 目标与完成标准

用户上传 DOCX 或 DOC 参考文档，填写写作要求并选择写作规范，由多模态模型依据全部文字、表格和原图生成指定段落或整篇文字。常用流程为“上传文档 → 填写要求 → 开始编写 → 预览使用”。

完成标准：请求确实包含全部支持范围内的资料内容和原图；不自动摘要、筛选或截断；支持段落与整篇输出；复用现有写作规范；异常不伪装成完整成功；插入操作不改错文档、不自动覆盖已有正文。

## 已确认的产品设计

### 参考文档

- 支持 DOCX、DOC，最多 5 份，使用当前文档所属的资料集，保留现有关闭重开、更新和移除行为。
- 每份显示文件名、读取文字数量、图片数量与状态，支持更换、移除。读取详情默认折叠。
- 所有已导入且有效的资料参加本次生成。用户需要缩减资料时主动移除，不增加默认隐藏的资料筛选。
- 原文件保持不变；DOC 在本机转换临时副本后读取。不能可靠转换时明确报错，不要求用户把 DOC 当作 DOCX 上传。

### 写作要求

- 一个多行提示词输入框，用于描述写什么、写一段还是整篇、篇幅、结构和语气；取消必填目标章节和读取所选章节的步骤。
- 紧凑的“写作规范”选择器复用智能编写的选项：自动匹配、G企技术材料、网络安全技术材料、党政公文、不使用写作规范。默认自动匹配，沿用已有匹配语义及提示。
- 共用规范库、匹配与应用能力，不复制一套规范数据。规范约束表达与术语，不得改变资料事实。资料作为输入内容，不得执行其中要求模型改变任务或泄露信息的指令。
- 不再把单独的“补充事实”输入框作为必经步骤。用户在提示词中明确提供的新事实作为用户补充标识；与资料出现实质冲突且未明确取舍时，列为待核对，不自行决定来源优先级。

### 生成结果

- 唯一主要操作为“开始编写”；读取或生成中显示实际阶段，生成中可取消，取消后保留资料与用户输入。
- 结果在同一窗格预览，支持复制和用户主动插入当前光标位置。首版不提供自动覆盖全文或替换选区入口。
- 出处、读取详情、缺项及待核对项默认折叠；有异常时显示简短醒目的数量或提示，不把异常藏在折叠内容中。
- 资料支持的事实应能追溯到文件和原文位置或图片；图片模糊、关键数值不可辨认或来源不充分时标为待核对，不编造。
- 生成失败保留输入；输出被模型长度限制中断时标为未完成，不展示为完整成果，也不自动多轮续写。

### Apple design 交互原则

系统字体、清晰留白、克制的层级和单一主按钮；保留现有独立模型设置入口，主流程不展示模型参数。按钮及时反馈，阶段状态就地显示，错误提供可执行的处理方式。折叠内容不改变输入焦点，支持键盘、可见焦点和减少动效偏好，不为外观引入新依赖。

## 全文与图片的处理约定

1. 读取正文、标题、列表、表格单元格文字及其行列关系，提取文档内图片，保留顺序、所属文件及与正文的锚定关系。文本框、页眉页脚、脚注尾注中的文字和图片纳入读取验收；重复内容可按原文引用关系表达，但不得丢失其位置含义。
2. 扫描页作为原图提交多模态模型。内嵌图片直接提交原图，不先转换为摘要或识别文字替代原图；不承诺仅靠识别消除模糊图片的不确定性。
3. 原生图表、公式、绘图和嵌入附件若无法提取为可读文字或可靠图像，列明未读取对象并阻止“全文已就绪”。不默认执行附件、宏或访问文档外链。外链图片不可获得时同样明确失败。
4. 生成请求包含全部资料文字、表格、全部原图、用户提示词和匹配的写作规范。图片使用稳定编号与正文对应；不调用现有相关片段筛选替代全文。
5. 预算核对包含系统提示、写作规范、全文、图片开销及输出预留；不沿用仅估算文字的检查来声称多模态容量充足。按实际模型/服务限制检查图片数、尺寸、请求大小与上下文，未知能力必须明确显示，服务端拒绝也原样归类为失败，不自动删图重试。
6. 超容量时提示更换支持更大输入的多模态模型，或主动缩减资料。不自动摘要、分段汇总、选择片段或截断。现有导入字数和文件安全上限继续保留，并与模型容量限制分别说明。

## 实现边界与复用方式

保留独立任务标识 `word.material_composer` 和现有模型配置，不合并到智能编写；复用已有后台任务、取消、资料归属、结果恢复和受控插入能力。

- 文档导入层：扩展 `adapter_service/app/services/word/material_import.py`，处理 DOC 转换、完整文字与图片提取、来源位置及可读性报告。解析和转换不得修改用户原文件。
- 生成层：调整 `material_composer.py` 与任务提示词，移除本任务对相关片段筛选、必填章节和仅章节输出的依赖。不要删除被 Excel/PPT 共用的辅助函数。
- 规范与模型层：接入现有 `writing_policy` 服务；复用 `provider_client.py` 的图片内容请求能力，补齐本任务的多模态能力检查与预算处理。已有图片请求通道不等于所有模型配置均支持图片。
- 接口层：前后端同步传递自由写作要求、规范选择和完整资料引用；资料内容及图片由后端装配，不通过扩大普通任务提交体来上传图片。FastAPI 与 standalone 保持行为一致。
- 窗格层：调整 `taskpane.html`、`taskpane.js`、样式和 `material-composer.js`，保留已有会话隔离与写入校验。旧章节草稿可继续预览、复制，不自动当作新任务重新提交。

生成使用提交时的资料、提示和规范快照。生成期间更换资料或切换目标文档，不允许迟到结果覆盖当前任务；旧结果保留所属会话。插入时重新校验当前文档和光标，保留现有安全检查和撤销能力；资料发生变更时提示重新生成，不沿用失效依据写入。

## 实施前需验证的环境能力

以下是验证任务，不是降低首版要求的替代方案：

- 在目标 Kylin V10/WPS 环境确认可用的本机 DOC 转换方式，验证文字、表格、图片及锚定关系不丢失。优先现有宿主能力；若必须新增依赖，先说明原因并取得用户确认。验证失败则 DOC 支持未完成，不按已支持交付。
- 使用实际配置的多模态模型验证图片通道、图像限制、容量计算和结构化结果兼容性。不自动更换模型或跨配置回退。
- 用真实文档核对浮动图片、扫描页、表格和非正文区域。未能完整提取时阻止生成并说明对象，不静默绕过。

## 验收与回归

1. 同内容 DOCX/DOC 各一份，含正文、跨页表格、内嵌与浮动图片；核对提取结果、顺序及原图实际进入模型请求。用文首、文中、文尾独立事实确认没有筛选遗漏。
2. 验证文本框、页眉页脚、脚注尾注及扫描页；不可读图片、损坏文件、加密文件和不支持对象均给出真实状态。
3. 同一资料分别生成一段和整篇，确认不存在“只写一个章节”的旧约束，输出达到用户提示要求。
4. 验证规范选择、自动匹配和禁用；确认复用同一规范库，术语和表达约束进入请求，未应用不能显示已应用。
5. 模拟文字、图片数、请求大小与总上下文超限，确认没有静默删减或纯文本降级；验证模型不支持图片和输出未完成的反馈。
6. 验证取消、重试、关闭重开、资料更换移除、切换文档及迟到响应；生成不自动写入，主动插入只影响正确目标。
7. 正式插件相关测试、`npm test`、`npm run build` 与受影响后端测试通过；按仓库文档使用 Kylin 当前虚拟环境解释器，完成 Python 3.8 兼容及差异检查。涉及交付时另做交付审计，不在设计阶段生成发布包。
8. 真实 WPS 和实际多模态模型验证可用性与生成质量，记录失败、耗时和未验证范围；模拟测试不得替代现场验收。

## 本轮范围外

不建设知识库、向量检索或图片摘要流水线，不自动分批编写长文章，不添加新的规范编辑器，不改造 Excel/PPT 业务，不发布安装包，不创建分支或 worktree。

## 实施补充（2026-09-28）

用户已明确不新增依赖。DOC 采用 WPS 自带 Documents.Open / SaveAs2 处理本机临时副本；必须能够关闭宏和自动外链更新，否则拒绝转换。该路径已通过模拟测试，不能据此宣称麒麟真机转换已验收。

现有模型配置没有通用可靠的图片 Token 计费信息，因此文字、规范及输出预留在本地核对；图片预算明确标为未知，由模型服务最终核验。保持现有每张原图 5 MiB 通道限制，不自动压缩、删图或转成文字摘要。真实识图能力仍需针对用户实际模型验证。
