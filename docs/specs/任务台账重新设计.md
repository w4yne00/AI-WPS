# 任务台账重新设计

日期：2026-09-29。状态：整体方案已确认；本规格待用户审核，尚未进入实施。

## 目标与完成标准

用户上传 DOCX、DOC、CSV、XLSX，或复用其他文档的材料，选择现有台账表头列并填写编写要求，由模型依据完整资料生成对应的表格项。常用流程为“添加材料 → 选择列 → 填写要求 → 生成预览 → 确认使用”。

完成标准：全部支持范围内的文本及表格进入模型请求；支持多模态的接入同时发送图片，不支持的接入只处理文本并明确提示；输出列及顺序符合选择；预览以表格为主、出处下钻；任务具有独立模型设置；保留现有确认写入及防覆盖措施。

## 已确认的产品设计

### 材料与全文输入

- 将上传与复用放在同一材料区，保留现有资料归属、更新、移除及独立副本语义。全部已添加且有效的材料参与生成，不增加隐藏的相关性筛选。
- 支持 DOCX、DOC、CSV、XLSX。列表显示名称、类型、读取状态；文字、表格、图片数量及读取详情按需展开。上传入口与真实后端支持同步，不以修改扩展名替代格式转换。
- DOC 通过 WPS 能力转换本机临时副本，再完整读取；关闭宏与自动外链更新，不修改原文件。Excel 宿主调用 Word 转换能力须在目标环境验证，不把 Word 宿主成功视为 Excel 已支持。
- DOCX/DOC 读取正文、标题、列表、表格及行列关系、文本框、页眉页脚、脚注尾注和可提取图片，保留内容顺序与来源位置。
- CSV 保留完整行列、空值、引号与换行内容，不只读取采样行；支持 UTF-8（含 BOM）及 GB18030，无法可靠解码时明确报错，不用替换字符掩盖损坏。
- XLSX 读取所有工作表的有效单元格内容，包含隐藏工作表、隐藏行列，并保留表名、单元格地址及合并关系；导入时提示包含隐藏内容。公式保留表达式与可用缓存值，不执行公式或外部链接；缺失缓存值标为未计算，不能当作空白事实。
- 复用材料须达到相同完整性要求；旧记录只有片段且无法重建全文时提示重新导入，不冒充全文。保留原来源与当前工作簿独立副本，更新不影响其他文档。
- 不静默摘要、截断或删掉文尾内容。文件安全限制、解析限制与模型上下文容量分别校验，沿用现有安全措施；超过限制时说明原因和可执行的处理方式。

### 图片与模型能力

- 用户已确认：支持多模态时提交完整文本、表格与图片；不支持多模态时仅处理完整文本及表格。
- 以现有模型与接入能力配置判断图片通道是否可用，不根据模型名称猜测。不能确认可用时按文本模式处理，并明确显示“未确认图片支持，本次仅处理文本”。
- 文本模式在生成前与结果中简短提示“图片内容未参与生成”，详情可查看涉及文件及对象数量。扫描页没有可读取文本时提示缺少可用文本，不生成貌似有依据的记录。
- 多模态模式发送可读取原图及其来源编号，不先用摘要或 OCR 替换原图。原生图表保留可读取的标题、标签和数据；能可靠获取图像时一并发送，不能获取时列明未读取的视觉信息。
- 文本模式允许跳过图片与纯视觉对象，但不能掩盖文字读取失败。多模态模式遇到无法读取的图片、图表视觉内容或嵌入对象时，明确报告未读取范围并阻止声称全文就绪；不静默退回文本模式。
- 不自动访问外链、执行附件或宏。损坏、加密、缺失对象等异常必须明确呈现。已判断支持图片但服务拒绝图片请求时，报告真实失败，不把超时、鉴权、容量等错误误判为模型不支持图片并自动重试。

### 表头与编写要求

- 保留“从选区读取表头”，将读取后的列显示为可勾选项，默认全选。用户可取消不需要的列，至少选择一列，输出保持所选列的原顺序。
- 表头读取要求为单行选区；空白或重名列显示就地提示，修正后再生成，避免模型字段无法对应。无现成表头时保留现有默认列和手动编辑能力，手动编辑默认收起。
- 用一个“编写要求”输入框描述任务范围、拆分方式及表达要求；现有“补充事实”移入可选展开区，保留已填写内容且明确标识，不让隐藏旧输入无提示地参与生成。
- 生成一行一项可独立跟踪的工作，允许根据提示组织表达，不限于原句摘抄。责任人、日期、数量等事实缺少依据时留空并标为待补充，不擅自编造。
- 保留已有事实冲突核对和疑似重复提示。实质冲突未解决时显示处理入口，不藏在普通详情里；疑似重复不自动合并。

### 结果预览与写入

- 结果表格占满预览区宽度，列多时在表格内横向滚动。每行只保留轻量“出处”入口，默认不并排展示来源面板或长篇引文。
- 点击出处后在同一预览区下钻，展示该行对应的文件、章节或工作表地址、原文及图片依据。提供明确“返回表格”，恢复横向及纵向位置与键盘焦点，参考 Word 按需编写已实现的行为。
- 页码只有可靠来源时显示；不能可靠获得时用章节、段落、表格或单元格定位，不编造页码。
- 缺项、重复及待核对内容默认显示数量，点击查看对应记录；资料失效、未完整生成等影响使用的状态保持可见。切换任务或工作簿重置详情，普通刷新不打断当前详情阅读。
- 保留复制表格及确认写入。出处入口、状态标记不混入复制和单元格数据。仅写入确认后的空白区域，不自动覆盖现有值或公式，不把列勾选解释为允许覆盖原台账。
- 沿用已有目标范围、会话、资料有效性、写入前核查和部分失败处理。生成或取消不修改工作表；输出截断、结构错误或来源无效时不能标为完成并开放写入。

### Apple design 与图标

- 主界面只突出材料、列选择、编写要求和一个“生成任务台账”主按钮；模型参数留在设置。复用系统字体、既有配色、清晰留白和即时状态反馈，不引入新 UI 框架。
- 读取及生成显示真实阶段，生成支持取消，失败保留用户输入。下钻与返回保持空间关系，兼容键盘、可见焦点、减少动效和高对比度偏好。
- 新图标采用“表格＋勾选事项”含义，遵循现有 Ribbon 图标尺寸与资产格式，避免细字及繁复装饰。最终在小尺寸及真实 WPS 工具栏检查辨识度，不单独建设图标系统。

### 独立模型设置

- 在 Excel 设置的模型配置中加入“任务台账”选项卡，继续使用 `excel.material_ledger`，不借用智能填写或 Word 的配置。
- 复用现有服务选择、任务模型、温度、最大输出 Token、上下文容量、验证调用及保存机制。默认值、空值和 0 的语义与现有编写功能保持一致，不另建一套参数规则。
- 配置须真正作用于台账请求与输入预算，提交时固定本次配置快照。修改台账配置不改变其他任务；验证调用继续沿用现有费用说明。
- 预算包含系统提示、用户要求、完整材料及输出预留；图片开销无可靠估计时明确为未知，由服务最终核验，不声称已经精确计算总容量。超限不自动删材料或降低输出要求。

## 实现边界与数据流

沿用当前工作目录，不创建分支或 worktree；不改动运行态配置及用户已有未提交文件，不新增依赖，确需依赖时另行说明并取得确认。

1. 材料层：扩展 `adapter_service/app/services/excel/material_store.py`，复用 Word 完整读取与安全转换能力，并为 CSV/XLSX 提供全文和来源位置。不要让 Excel 的文本降级规则改变 Word 现有行为。
2. 生成层：调整 `adapter_service/app/services/excel/material_ledger.py` 与 `system_prompts/excel-material-ledger.md`，从完整资料快照构造输入，带入所选表头、提示和补充事实，沿用后台任务、取消及结构化结果验证。
3. 模型与接口：复用 `provider_client.py`、现有模型配置和图片发送能力。任务提交只传材料引用及用户选择，后端装配全文与图片；FastAPI 与 standalone 的导入、提交和错误行为保持一致。
4. 窗格层：修改 Excel 插件的 `material-ledger.js`、`taskpane.html`、`taskpane.js`、相关样式与 Ribbon 图标映射；复用 Word 下钻行为，不跨宿主搬入整套页面。
5. 数据流：上传或复用 → 完整读取及来源登记 → 选择表头与模型 → 冻结本次材料和参数 → 核对输入容量 → 调用模型 → 验证列、事实出处和完成状态 → 表格预览 → 用户确认后沿用现有写入流程。

切换工作簿、修改材料或重新生成时，迟到响应不能覆盖当前结果。旧结果可按现有历史能力查看，但不得绕过失效核查直接写入。文档文字只作为资料，不得执行其中指令。

## 验收与回归

1. 四种格式分别包含文首、文中、文尾独立事实；检查实际请求完整包含这些内容、表格行列和来源位置，不仅检查 UI 或最终回答。
2. 验证 CSV 编码、带引号换行和空值；XLSX 多工作表、隐藏内容、合并单元格、公式缓存缺失；损坏和加密材料明确失败。
3. 验证 DOC 在 Excel 宿主的真实转换、原文件不变、临时文件清理与安全开关。真机失败则 DOC 支持未完成，模拟测试不能替代。
4. 同一带图材料分别使用多模态与文本模型：前者请求含图片，后者含完整文本且不含图片，并显示忽略范围；纯扫描材料无可用文本时明确提示。能力未知、图片拒绝和容量超限分别验证。
5. 验证现有资料复用和旧片段记录：独立副本不互相改写，缺少完整材料不能静默参与全文生成。
6. 验证表头勾选、顺序、空白及重名处理；提示驱动编写、缺项留空、冲突核对、来源有效性及输出截断处理。
7. 在 320px、420px 窗格验证表格、横向滚动、出处下钻、返回位置及焦点恢复、缺项详情和键盘操作；检查新图标的小尺寸可读性。
8. 保存并重开任务台账模型设置，检查温度、最大输出 Token、上下文容量实际进入调用与预算，其他任务配置不变。
9. 验证取消、重试、切换工作簿、资料更新、迟到响应和旧预览失效；写入只影响已确认空白区域，复制数据不含 UI 装饰。
10. 运行受影响后端及正式插件测试，再执行仓库要求的 `npm test`、`npm run build`、`node --test formal-plugin-kit/tests/*.test.js`。后端按 `docs/operations/kylin-v10-test-environment.md` 使用当前虚拟环境解释器；完成 Python 3.8 兼容检查与差异检查。发布交付包时另做交付审计。
11. 真实 WPS 和实际模型验证操作、识图和生成质量；报告通过数、失败数、关键问题、影响范围及未验证项，不将模拟结果表述为真机验收。

## 本轮范围外

不建设知识库、向量检索、自动分批摘要或自动续写；不重构其他功能，不新增 OCR 服务，不执行材料中的宏或外链，不自动覆盖已有台账，不在设计阶段生成安装包。

## 规格自检

通过 4 项，失败 0 项：无占位要求；全文与文本降级规则一致；范围集中于任务台账；列映射、未知图片能力、超限和写入边界已明确。目标机 DOC 转换、真实模型图片能力及实际生成质量待实施阶段验证。
