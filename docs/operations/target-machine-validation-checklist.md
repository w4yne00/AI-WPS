## 核心检查项

- [ ] 目标机为麒麟 V10
- [ ] 架构为预期 ARM / `aarch64`
- [ ] WPS 二进制存在
- [ ] Python 版本符合预期
- [ ] 探针插件可导入
- [ ] 导入目录命名满足 `<插件名>_<版本号>`
- [ ] 任务面板可打开
- [ ] `Runtime Probe` 可返回结果
- [ ] localhost 适配层连通性结果已记录
- [ ] 已生成验收记录

## Word 选区事件与兜底监听（issue #16）

测试环境记录：

- WPS 版本：`________________`
- `wps.ApiEvent.AddApiEventListener` 是否可用：`是 / 否`
- `WindowSelectionChange` 是否实际触发：`是 / 否`
- 验收人及时间：`________________`

按下列顺序在 Word 任务窗格执行；“立即”以 1 秒内为验收口径，“低频兜底”以约 2 秒、最长不超过 3 秒为现场口径。

| 场景 | 操作 | 预期结果 |
| --- | --- | --- |
| 事件路径 | 保持任务页可见且模型空闲，在正文和有效选区之间切换 | 若宿主实际触发 `WindowSelectionChange`，范围摘要立即在“全文 / 选中文本”间切换 |
| 事件漏报 | 在已确认事件可用的环境中连续用鼠标、键盘及跨窗口方式改变选区 | 漏报时范围摘要仍在 3 秒内由低频兜底修正，不会永久停留在旧范围 |
| 事件不可用 | 在不提供或不触发 `WindowSelectionChange` 的麒麟/WPS 组合上改变选区 | 页面不报错，范围摘要在 3 秒内更新；记录该环境使用兜底路径 |
| 页面隐藏 | 隐藏任务窗格后改变选区，等待至少 3 秒，再重新显示任务窗格 | 隐藏期间不持续刷新；重新可见后立即显示当前真实范围 |
| 设置页 | 进入设置后改变选区，等待至少 3 秒，再返回任务页 | 设置期间暂停选区读取；返回任务页后立即显示当前真实范围 |
| 模型任务 | 分别在四个 Word 任务请求运行期间改变选区 | 请求期间暂停无意义读取；任务完成或失败后立即恢复并显示当前范围 |
| 无变化播报 | 保持选区不变并停留任务页至少 10 秒，同时开启屏幕阅读器或可访问状态检查 | 低频兜底不重复改写或播报相同的范围摘要 |

回归检查：

- [ ] 智能编写仍要求有效选区，抽取和写回仅作用于原选区边界。
- [ ] 智能仿写仍只将选区用于模板预填，结果保持预览/复制，不新增写回。
- [ ] 文档审查仍按选区优先、无选区全文的既有边界工作，并保持后台任务恢复。
- [ ] 格式审查仍按既有限量抽取和只读结果工作。
