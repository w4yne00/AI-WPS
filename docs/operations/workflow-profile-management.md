# AI-WPS 模型配置管理

## 适用范围

`v0.23.0-alpha` 起，八类任务统一使用按任务隔离的“模型配置”。Word、Excel、PPT 只显示当前宿主已有功能的配置选项卡，互不交叉：

- Word：智能编写、智能仿写、文档审查、格式审查。
- Excel：智能分析、公式助手。
- PPT：智能总结、结构审查。

每项任务可保存多个配置，任务页下拉菜单只显示字段完整的配置。选择后立即生效，但不会改变已提交后台任务的认证和参数快照。

## 接入方式

### 工作流平台

用于兼容提供类 Dify Chat API 的工作流平台。每个配置独立保存：

- 配置名称和可选备注；
- 服务地址；
- API Key；
- 固定应用路径 `/chat-messages`。

Adapter 继续兼容旧版 `inputs.query` 和新版顶层 `query/files` 输入方式。界面和日志不把具体平台品牌作为通用功能名称。

### 模型直连

用于兼容 OpenAI Chat Completions 协议的模型网关。已知目标包括 GLM 5.2 和 DeepSeek V4 Flash，默认按 40K 上下文容量管理。每个配置独立保存：

- 配置名称和可选备注；
- 服务地址，例如 `http://1.1.1.1:1111/one-api/v1`；
- API Key 和模型标识；
- 高级配置中的温度、最大输出 Token、上下文容量；
- 固定应用路径 `/chat/completions`。

Adapter 将对应任务的版本化 System Prompt 与用户输入分别放入 `system`、`user` 消息。八类 System Prompt 位于 `adapter_service/system_prompts/`，启动和交付构建会按清单哈希校验。

## 新建与验证

1. 打开当前宿主的“设置”。
2. 选择任务选项卡，点击“新建模型配置”。
3. 填写接入方式、服务地址、配置名称和对应字段。
4. API Key 需输入两次；也可以先保存不完整配置，稍后补充。
5. 完整配置可设为当前，并可在“高级配置”中执行一次验证调用。

验证调用会真实访问模型后台。失败只记录到当前配置，不会自动切换或重放到其他配置。

对 `word.format_review`，工作流平台验证四类 `format_semantics.v1` 操作；模型直连验证生产格式语义契约的 `classify_role` 操作。验证请求只包含合成候选和快照绑定，不包含用户文档或密钥正文。验证接口返回当前配置的名称、ID、修订号、是否为当前配置以及当前配置 ID；未激活的成功配置会明确显示“当前任务不会使用此配置”。

## 修改、复制与删除

- 留空 API Key 保存时，原 Key 保持不变。
- 切换接入方式会清空原方式专属参数和 API Key，界面必须二次确认。
- “复制”创建同任务的未激活副本，不复制密钥正文；补齐并验证后再启用。
- 当前配置不能直接删除，应先切换到其他完整配置。
- 删除配置会删除其独立密钥文件，无法恢复。

## 旧配置迁移

首次启动 `v0.23.0-alpha` 时，原工作流档案会原位迁移为 `workflow_platform` 模型配置，复用原密钥引用，不移动、不覆盖、不删除密钥文件。旧 `/provider/workflow-profiles` API 保留一个版本作为兼容包装，新前端使用 `/provider/model-configurations`。

运行时不再从统一 URL 或统一 Key 回退。迁移后的配置必须具有服务地址和 Key 才能激活；不完整配置保留在设置页，便于用户补齐。

## 存储与升级保护

- 非密钥配置保存在 `config/adapter.json`。
- API Key 正文保存在 `run/provider_api_keys/`，文件权限为 `0600`。
- 查询、诊断和日志不返回密钥正文。
- 覆盖安装必须备份并恢复 `config/adapter.json`、`run/provider_api_key`、`run/provider_api_keys/` 和写作规范数据库。
- 交付包不得包含开发机的 `adapter.json`、数据库、备份、日志或任何 API Key。

## 故障排查

1. 确认任务页下拉菜单中存在目标配置；未出现表示配置不完整。
2. 在设置页核对服务地址、接入方式、Key 状态，以及直连模式的模型标识。
3. 保存后执行“验证调用”，查看耗时和错误摘要。
4. 在“高级诊断”核对配置 ID、接入方式、请求路径、System Prompt 版本和错误码。
5. 长任务已提交但任务窗格短暂断开时，不要重复提交；重新打开对应任务页，让前端按本地任务编号恢复查询。
