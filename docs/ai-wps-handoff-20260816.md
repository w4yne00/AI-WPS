# AI-WPS 会话交接（2026-08-16）

## 当前目标

先收敛 `v0.25.1-alpha` 的 Word 格式审查阻断缺陷并完成目标机验收，再以 `v0.26.0-preview.1` 建立新的 Preview 安装和升级基线。素材编排及共享本地文档抽取属于后续功能线，不与当前格式审查修复混合实现。

本轮只完成问题诊断、ADR 与领域文档整理，没有修改生产代码或测试代码。

## 格式审查已确认根因

目标机截图显示“识别来源：本地规则”，并重复报告 `P0 未识别角色 - 标题层级出现跳级`，当前值为 `10`。这不是标准文档自身的标题层级错误，也不是模型配置最大 Token 不足。

1. WPS Word 使用 `OutlineLevel=10` 表示正文，但当前前端把任何大于零的值当作标题层级。
2. 正文因此被构造成 `headingLevel=10`；后端继续把它当作已确认标题，标题层级算法产生大量跳级问题。
3. 已确认角色不会进入模型模糊候选，所以本次 `aiCandidateCount=0`、`aiAttempted=false`、模型调用数为零，结果来源自然显示为本地规则。
4. 后端层级问题使用通用角色 `heading` 且没有段落索引；前端只映射 `heading1` 至 `heading4`，并把缺失索引显示成 `P0`，最终形成“P0 未识别角色”的误导文案。

因此，“验证调用成功”与“正式审查没有调用模型”并不矛盾。前者只证明独立探针请求成功，后者因错误的确定性分类没有生成模型候选。

## 验证调用的独立缺陷

模型直连的现有验证探针仍使用旧 JSON 数组，只检查基础角色分类结果；正式格式语义运行要求严格的 `format_semantics.v1` 对象、operation、snapshotBinding 和 items。验证成功不能证明真实格式语义协议可用。

模型配置的“验证成功”和“设为当前配置”也是两个独立状态。后续界面必须明确显示：

- 已验证但不是当前配置；
- 当前任务实际使用的配置 ID、名称和修订；
- 模型是否尝试、调用次数、候选数和稳定降级原因；
- 模型尝试后零结果被接受时的协议、解析或置信度原因。

## v0.25.1-alpha 修复范围

建议按以下顺序实现，不与 ADR-0116/0117 的新功能混合：

1. 前端统一规范化大纲级别：`1..9` 为标题，`0` 或 `10` 为正文，其它值为未知；后端再做同样的防御校验，禁止把非法 `10` 裁剪成标题九级。
2. 增加真实 WPS `OutlineLevel=10` 正文回归测试；现有测试把正文模拟为 `0`，无法覆盖目标机行为。
3. 层级问题保留真实段落索引和明确角色类型；前端支持通用标题角色，不再把缺失索引显示为 `P0`。
4. 让模型直连验证调用使用与正式运行相同的 `format_semantics.v1` 合成候选，至少覆盖 `classify_role`，并增加协议一致性测试。
5. 在结果摘要公开模型尝试、调用数、候选数、实际配置和降级原因，区分“无需调用”“调用失败”和“调用后结果被拒绝”。

格式审查仍遵循 ADR-0066 的确定性优先边界：模型只补充模糊角色和语义关系，不覆盖字体、字号、页边距等可验证规则结论。

## 后续需求决策

- ADR-0116：将 PPT 专属的 Markdown/DOCX 本地抽取和安全暂存能力提升为宿主无关共享模块；先做无行为变化的抽取边界重构。
- ADR-0117：新增独立任务 `word.material_composer`，拥有自己的模型配置、API Key、任务系统提示词和后台任务身份。
- 素材编排首版限一份素材、单轮、不附带当前文档、超预算拒绝。素材不被修改；结果支持预览、复制和用户明确触发的光标插入，不执行全文替换。
- `docs/known-defects.md` 的 D-0001 是 DOCX 本地抽取 styleId 解析缺陷，与本次 WPS `OutlineLevel=10` 格式审查缺陷是两条不同链路，应独立修复和验收。

推荐顺序：格式审查阻断缺陷与 `v0.25.1-alpha` 目标机验收 → ADR-0116 共享抽取纯重构及 D-0001 修复 → ADR-0117 素材编排最小闭环。

## 版本和安装基线

- `v0.25.1-alpha` 是沿用现有 Phase1 安装体系的最后一个 Alpha 收敛版本。
- `v0.26.0-preview.1` 正式进入 Preview，使用中性包名、安装根、脚本名和发布标识。
- 该切换允许用户进行一次重新安装并重新配置全部参数和目录文件；不自动迁移或删除旧安装，不保留 Phase1 入口兼容承诺。
- 产品成熟度通道 `alpha/preview` 与构建验证状态 `candidate/target-accepted/rejected` 分开表达，Preview 候选不等于已经目标机验收。
- `v0.26.0-preview.1` 是后续升级基线。此后采用保留配置和运行数据的兼容升级，或严格声明起始基线的增量升级包，不再以全量重装作为常规升级方式。

详细决策见 ADR-0118。

## 工作区与安全约束

- 当前分支为 `main`。工作区仍有用户既有的代码修改、历史交付包删除、配置、运行目录和临时文件；不得清理、还原或夹带提交。
- `config/adapter.json`、`run/`、`.scratch/`、历史交付包删除和本轮无关代码均不属于文档同步范围。
- 实施代码修复前必须重新核对 `docs/codex-handoff.md`、相关 ADR 和测试要求；不得输出 API Key 或未脱敏请求内容。
