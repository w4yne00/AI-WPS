# 按需编写实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** 上传 DOCX/DOC，以全文、表格、原图及现有写作规范驱动多模态模型生成段落或整篇文字。

**Architecture:** 扩展现有资料导入和独立 `word.material_composer` 任务；后台组装全文及原图，沿用任务队列、会话隔离和受控插入。共享写作规范服务与图片请求通道，不重构 Excel/PPT。

**Tech Stack:** Python 3.8、FastAPI、standalone Adapter、WPS JS/HTML、Node.js/Vite/Vitest。

**Spec:** `docs/specs/按需编写重新设计.md`（已获用户确认）。用户已确认，并选择当前会话实施、完成后独立审查。

## Global Constraints

- 最多 5 份 DOCX/DOC；保留现有导入字数、文件安全和请求边界，不擅自扩大限制。
- 全文、表格和全部原图参加生成，不自动摘要、筛选、删图、截断或分批续写。
- 共用智能编写规范库；保持独立模型配置，不跨配置回退。
- 不修改原文件，不自动写入；只在用户主动操作后插入当前光标位置。
- 留在当前工作环境，不创建分支或 worktree；已有未提交修改不得覆盖或一并提交。
- 新依赖先说明并获得确认；不修改或提交 `config/adapter.json`、`run/`、本地审查资料。
- 测试成功后按任务提交明确文件；提交前检查差异和 Python 3.8 兼容性。不生成安装包或发布。

## Review Focus

- DOC 转换表面成功但浮动图片或非正文文字丢失：任务 1、2 核对转换前后人工标注内容。
- 同一图片被多处引用、表格嵌套或页眉重复：任务 2 保留内容与位置关系，防止漏项及重复统计失真。
- 模型接受图片字段却未理解图片：任务 3、6 使用只有图片提供答案的真机样例验证，不把 HTTP 成功当作识图成功。
- 规范失效、资料内恶意指令及提示与资料冲突：任务 4 保证事实边界及真实应用状态。
- 取消或切换文档后的迟到响应、重开旧草稿：任务 5、6 保留归属，防止错误插入。
