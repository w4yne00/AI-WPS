# 资料大纲重新设计实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** 让 PPT 资料大纲使用 DOCX/DOC 的完整文字、表格和原图生成逐页建议，提供出处下钻及独立模型设置。

**Architecture:** 复用 Word 完整读取、多模态请求和既有安全转换流程，扩展 PPT 材料存储与现有后台生成任务。保留当前资料会话、确认大纲及模板生成接口语义，仅增补建议字段与来源能力；预览借鉴 Word 同区下钻。

**Tech Stack:** Python 3.8、FastAPI、Pydantic、standalone Adapter；WPS JS/HTML/CSS、Node.js、Vitest。

**Spec:** `docs/specs/资料大纲重新设计.md`（用户已确认）。用户选择当前会话逐项实施，完成后独立审查；2026-09-30 已完成源码与自动化回归，现场验收项保留未完成。

## 全局约束

- 保留当前工作目录和分支，不创建 worktree，不修改运行态配置及用户已有未提交文件。
- 新增依赖须先说明并取得确认；不为动画新增依赖。
- 完整文字、表格和原图同时交给支持图片的模型；不自动 OCR 替代原图、不删图、不压缩为摘要、不分段汇总。
- 沿用现有最多五份资料及文件安全限制，所有已添加且有效的材料参与生成，不增加隐藏筛选。
- 模型参数沿用既有空值、零值及默认语义；图片预算未知明确标注，不伪称精确容量。
- 生成只产出大纲，不修改幻灯片；真实 WPS DOC 转换与真实模型识图须单独验收。
- 不发布安装包，不修改现场配置；每次提交只列出本任务文件，禁止 `git add .`。

## 审查重点

1. 其他宿主资料列表混有 CSV/XLSX 或缺原件的历史材料：不伪装为完整 Word 输入（任务一）。
2. 两份文档均有同名图片编号、相同段落编号：引用仍定位正确文件及图片（任务二）。
3. 配置中的温度为 0、输出参数留空、上下文为 0：不被真值判断误替换，遵循既有配置规则（任务三）。
4. 用户在出处详情打开时切换演示文稿、旧生成任务随后返回：不串会话或覆盖新内容（任务四）。
5. 旧大纲没有新增建议字段，新大纲编辑后继续模板生成：可读取且正确失效、重新确认（任务二和五）。
