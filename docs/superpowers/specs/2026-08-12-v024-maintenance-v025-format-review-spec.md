## Problem Statement

AI-WPS 当前开发已经进入 `v0.24.0` Word 全篇文档审查功能线。该功能的主体实现由 Issue #35 至 #40 逐步完成，最终白名单交付包和麒麟 V10、目标 WPS、`cloud` 用户验收仍分别由 Issue #41、#42 追踪。此前的合并规格仍把确定性格式审查及三宿主体验改造安排在 `v0.24.0`，已经不符合当前版本进度，并会使同一个版本同时承担文档审查验收、文档审查缺陷修复和另一套大型格式审查状态机。

文档审查上线或验收中发现缺陷时，需要保持在 `0.24.x` 版本线上进行补丁位迭代，以便修复能够独立构建、回归和交付，而不被未来格式审查功能阻塞。这里的“小版本号迭代”按现有版本结构落实为 `0.24.1`、`0.24.2` 等补丁版本；是否保留 `-alpha` 后缀继续遵循项目交付规则。

Word 格式审查仍需要按已经确认的确定性优先方案重构：本地规则负责所有能够从格式事实确定的结论，模型只处理无法确定的段落角色、语义关系及缺失图题/表题建议；受支持图片由 WPS `SaveAsPicture` 只读导出为 PNG，图片语义能力首版随包休眠且默认关闭。同时，Word 设置页需要对齐 Excel/PPT，三宿主任务页模型配置标签需要精简，Excel/PPT 重复 Ribbon 图标需要替换。

这些格式审查和体验改造统一属于 `v0.25.0`。在 `v0.24.0` 的目标机验收 Issue #42 关闭之前开始 `v0.25.0` 代码开发，会让新功能建立在尚未被目标环境证明的文档抽取、任务协调、生命周期和交付包基线上，因此必须设置明确、可检查的开发门禁。

## Solution

建立两条严格分离的版本线和一个状态型前置门禁。

`v0.24.0` 只完成 Word 全篇文档审查及其交付验收。文档审查或其共享基础能力发现缺陷时，以 `0.24.x` 补丁版本修复、测试和交付，不混入格式审查、图片语义或三宿主体验新功能。补丁修复在后续 `v0.25.0` 基线上前向合并，避免同一缺陷出现两套实现。

`v0.25.0` 统一交付确定性优先格式审查、受限模型语义、默认关闭的图片语义能力，以及此前确认的 Word 设置页对齐、任务页配置标签精简和 Excel/PPT Ribbon 图标替换。格式审查的既有容量、安全、协议、报告和生命周期决策继续有效，但不再属于 `v0.24.0`。

GitHub Issue #42 的状态是 `v0.25.0` 代码开发的硬门禁。只有 #42 为 `CLOSED` 时，才允许创建或修改实现 `v0.25.0` 行为的生产代码、测试代码、API/Schema、资源、清单、版本声明和交付脚本。在 #42 关闭前，可以继续完善规格、ADR、tickets、验收样例和只读技术调研。若 #42 后续重新打开，则暂停新的 `v0.25.0` 实现、集成和打包，保留已有工作，待门禁再次满足后继续。

最高测试接缝继续使用已经确认的“最终白名单交付包的三宿主行为契约”。`0.24.x` 在该接缝验证文档审查补丁没有破坏当前能力；`v0.25.0` 在 #42 关闭后以已验收的最新 `0.24.x` 基线验证格式审查和三宿主体验改造。

## Implementation Decisions

- `v0.24.0` 是当前 Word 全篇文档审查功能版本；Issue #35 至 #40 的关闭记录构成已完成实现事实，Issue #41、#42 继续完成交付包和目标机验收。
- 文档审查发现的缺陷进入 `0.24.x` 补丁线。补丁位从当前已交付或候选版本顺序递增；预发布后缀继续遵循项目既有规则。
- `0.24.x` 只允许文档审查缺陷、其直接依赖的共享基础修复、必要测试、版本和交付变更，不加入计划中的格式审查、图片语义或三宿主体验新功能。
- 每个补丁必须具有明确复现条件、受影响范围、回归测试、独立版本身份、白名单产物、哈希和回退证据。
- `v0.25.0` 基于 Issue #42 已验收的 `v0.24.0`，并包含之后所有适用的 `0.24.x` 修复；共享缺陷优先在 `0.24.x` 修复，再前向合并到 `v0.25.0`。
- Issue #42 的 GitHub 状态是 `v0.25.0` 代码开发门禁。只有状态为 `CLOSED` 才可开始实现；标题、评论、人工口头确认或本地标记不能替代关闭状态。
- 门禁覆盖生产代码、测试代码、协议和 Schema、静态资源、第三方内置代码、配置迁移、版本清单、打包与交付脚本。规格、ADR、tickets、测试样例设计和只读调研不属于代码开发，可在门禁前完成。
- 所有 `v0.25.0` 实现 tickets 必须声明 `Blocked by #42`。agent 开始任何实现 ticket 前必须实时读取 #42 状态，不依赖创建 ticket 时的状态快照。
- Issue #42 若重新打开，暂停新的 `v0.25.0` 代码、集成、构建和发布；已有工作不删除，待 #42 再次关闭并复核基线后继续。
- `v0.25.0` 格式审查使用独立于全篇文档审查的格式快照、格式语义模型、任务和报告协议，但复用已验收的秘密上传会话、任务协调器、公平让位、生命周期和白名单交付模式。
- 已获作者授权的 `wx-doc-format-skill` 确定性算法以固定来源版本内置并适配 Python 3.8；上游默认模板值、默认样式名称和自动排版写回不进入 AI-WPS 权威规则。
- 格式规则包由权威模板事实和人工审定结构规则编译，记录来源、版本、单位、容差和适用角色；编译差异未确认时不得发布。
- 格式审查首版覆盖正文故事中的页面、节、段落、字符同质区段、标题、列表、表格、题注、目录、注和附录；页眉页脚尽力读取，其他不支持对象只盘点和披露。
- 全文和选区共用引擎；选区扩展到完整语义单元，只读取必要上下文，范围外不得产出问题，全文连续性规则列为未执行。
- 格式快照分批上传并执行第二遍结构和格式指纹验证；结构、对象计数、覆盖统计或参与审查属性变化时删除快照并要求重试。
- 混合字符格式通过递归二分同质 Range 并合并相邻相同区段；达到碎片化上限时标记数据不足，不逐字符无限扫描。
- 容量分为不超过 60,000 审查字符、60,001–120,000 和超过 120,000 明确拒绝，同时执行内容块、表格单元格、格式区段、不支持对象和累计字节复杂度门禁。
- 格式语义角色与模板规则键分离。样式名称、OutlineLevel、编号外观、文本模式、位置和相邻关系只是来源可区分的证据；证据不足或冲突时形成模糊候选。
- 模型只允许角色分类、题注关联、图题建议和表题建议，并绑定快照指纹和稳定块标识；置信度低于 `0.85` 或与确定性证据冲突时不得进入规则结论。
- 表格只有具备明确表头、重复行结构、稳定列语义或多行记录等正向证据时才确定为数据表；首版不让模型分类表格类型。
- 题注关联和题注位置分别判断；候选关系必须来自同节、同正文故事的预计算有限集合，关联未决时不得同时确认对象缺题注。
- 图题和表题始终是只读建议。模型只返回最长 80 个 Unicode 字符的题注正文，不含前缀、编号、Markdown、换行或解释；编号由确定性规则计算。
- 表题建议只处理确定为数据表且缺表题的对象，使用完整表头、合并关系、行列数、单位、来源、表下注、所在标题和邻近上下文；超预算时明确使用首三行和末两行受限样例。
- 单次格式语义估算输入最多 8,192 Token。工作流平台使用明确的 2,048 最大输出；模型直连读取当前配置，空值按精确模型能力表计算，任务有效输出仍不超过 4,096 Token。
- 一次格式审查最多 16 次模型调用，重试和纠正计数；单次最长 60 秒，全部语义阶段含重新排队最长 10 分钟，调用串行并在完整批次后释放共享长任务槽。
- 任务提交时冻结模型配置修订、认证快照、调用方式、地址、模型标识、上下文、输出、System Prompt、规则包和能力表版本；运行中配置变化只影响新任务。
- 报告分别返回执行、合规、覆盖和语义增强状态。只有执行完成、覆盖完整、必需规则全部执行、无未决角色且无违规时显示通过。
- 格式问题由规则标识、稳定格式锚点和属性路径识别，记录当前值、期望值、单位、容差、证据、数据状态、规则和模板版本以及模型来源与置信度。
- 终态前只返回阶段和计数；格式快照、文本、候选和模型上下文在终态立即删除，分页结构化报告保留 24 小时，Markdown 由结构化报告导出。
- Dify 工作流实现 `format_semantics.v1` 固定输入输出契约。AI-WPS 不覆盖用户 System Prompt；白名单包提供文本版和视觉版参考 DSL，安装器不自动导入或覆盖。
- 图片语义实现随 `v0.25.0` 休眠交付，总开关在新安装和升级后为 `false`；关闭时不得创建槽位、调用 `SaveAsPicture`、生成 PNG 或上传像素。
- 视觉关闭不影响图片盘点、缺图题、题注位置和文字证据规则；文字证据不足时返回不可判断，不允许文本模型假装看过图片。
- 后续启用要求管理员打开总开关，每个模型配置显式声明图片输入模式、图片外发授权，并通过与配置修订绑定的合成视觉能力验证。
- 视觉首版只处理正文故事中的受支持内嵌、浮动及可安全导出像素的链接图片。WPS 仅使用 `SaveAsPicture` 只读导出 PNG，不使用 Pillow、不提取 OpenXML 原图、不保存文档。
- Adapter 为图片分配受控随机槽位并校验路径边界、普通文件、非符号链接、属主、PNG 签名、尺寸、大小和 SHA-256。单图不超过 5 MiB、8,192 单边和 2,000 万像素。
- 每次视觉调用处理一个完整图对象组，最多四张图片。图片只在获得预算后逐组导出，组内任何失败则整组不发送，批次及重试结束后立即删除。
- 图片阶段在每组导出前后验证文档身份、编辑状态、锚点、类型、数量、尺寸和邻近文本指纹；任何编辑立即停止剩余导出。
- Word 设置页对齐 Excel/PPT 的状态条、模型接口卡、任务选项卡、配置列表、编辑子页及诊断层级，并统一 36 像素控件基线、6 像素控件圆角、8 像素面板圆角和完整交互状态；保留 Word 强调色与写作规范库。
- 三宿主任务页模型配置标签统一为 `配置名称 · 工作流平台` 或 `配置名称 · 模型直连`，不显示模型标识、地址、Key、备注、完整度或激活符号；设置页继续显示管理所需信息。
- Excel 公式助手采用 Fluent `Math Formula 32 Regular`，PPT 结构审查采用 `Slide Text Multiple 32 Regular`；转制为本地透明 32×32 PNG，记录上游版本、许可、来源和哈希，目标机不联网加载。

## Testing Decisions

- 测试只验证可观察行为、公开协议、文件系统结果和数据生命周期，不锁定私有函数或临时实现细节。
- 最高测试接缝保持为最终白名单交付包的三宿主行为契约；API、Node 契约、资源审计和目标机验收是该契约的分层证据。
- Issue #42 关闭前不新增或修改任何实现 `v0.25.0` 行为的测试代码；此阶段只允许规格结构检查、测试样例设计和 `v0.24.0` 交付验收。
- 每个 `0.24.x` 补丁先加入能复现缺陷的最高可用接缝测试，再验证修复，并运行文档审查公开 API、Word 插件契约、共享协调器、生命周期和最终交付包相关回归。
- `0.24.x` 目标机验收按风险选择受影响场景，但升级、版本、哈希、配置/Key/规范保持、只读边界和回退证据始终必测。
- `v0.25.0` 测试只在 #42 关闭后开始落地，并以已验收的最新适用 `0.24.x` 白名单交付包作为升级基线。
- 格式审查 API 端到端复用全篇审查的秘密会话、连续批次、隔离存储、可控时钟和共享协调器夹具，但使用独立格式快照与报告 Schema。
- 确定性规则测试以规范化格式语义模型和编译规则包为接缝，使用授权上游黄金案例及 AI-WPS 反例，证明相同事实产生稳定结论且第三方默认模板值不进入权威规则。
- 自动化覆盖全文/选区、语义扩展、范围外隔离、未执行全局规则、两遍格式指纹、纯格式编辑中止、混合字符区段和复杂度拒绝。
- 自动化覆盖角色证据冲突、0.85 门槛、未知角色、未配置映射、数据表正向证据、题注关联/位置分离和歧义关系。
- 模型契约使用假工作流和假直连 Provider，覆盖四类操作、快照绑定、8,192 输入、2,048/4,096 输出、16 次调用、超时、重试、纠正、串行、公平让位和取消。
- 自动化覆盖 Dify `format_semantics.v1`、旧工作流保留、未验证时确定性降级、参考 DSL 不自动导入及题注建议事实约束。
- 视觉默认关闭测试从最终包证明不开槽、不导图、不上传、不标记像素已检查，同时仍执行确定性图片规则。
- 图像安全测试覆盖受控槽位、路径穿越、符号链接、伪 PNG、哈希变化、尺寸/大小门禁、1–4 图原子组、预算、编辑中止和终态清理。
- 三宿主 UI 契约覆盖 Word 设置结构和状态、窄窗折行、配置下拉标签、稳定 option 节点，以及 Excel/PPT 不同 Ribbon 图片映射。
- 交付审计覆盖 Fluent 资产、版本、许可证、版权、原始/派生哈希、白名单和引用闭包，并证明目标机无网络资源依赖。
- 麒麟 V10/WPS 真机验收覆盖 60,000 与 120,000 字符格式抽取、复杂表格、混合格式、选区、取消/编辑、报告定位、Word 文档只读和三宿主 UI；休眠视觉能力只验证默认关闭，未来启用前另做专项 `SaveAsPicture` 验收。

## Out of Scope

- 在 Issue #42 关闭前实现、测试、集成、构建或发布任何 `v0.25.0` 功能代码。
- 把格式审查、图片语义、Word 设置页重构、任务标签精简或 Ribbon 图标替换加入 `0.24.x` 补丁版本。
- 为了等待 `v0.25.0` 而延迟已确认的文档审查缺陷修复。
- 在本规格中重新定义 Issue #42 的验收条件；其关闭状态由该 Issue 自身的验收流程产生。
- 使用日期、里程碑名称、本地文件或人工口头确认代替 Issue #42 的 GitHub `CLOSED` 状态。
- 自动套用、修复或写回格式审查结论。
- 让模型替代确定性规则、自由发现审查对象或修改格式标准。
- 将第三方默认模板值作为 AI-WPS 格式标准。
- 默认开启图片像素导出和外发，或声称文本模型已经查看图片。
- 使用 Pillow、提取 OpenXML 原图、自动压缩超限图片或发送不完整多图对象组。
- 承诺远端模型平台已经删除图片。
- 在任务页配置下拉展示模型标识，或从设置页移除模型标识。
- 目标机运行时联网下载 Ribbon 图标。
- 与格式审查无关的大规模代码重构。
