## Problem Statement

目标机从前一版本升级到 `v0.23.0-alpha` 后，Adapter 在 Python 3.8 导入阶段因使用仅兼容 Python 3.9 及以上的内置容器泛型注解而退出，未监听本地 18100 端口。WPS 因此无法读取八类既有工作流平台配置和 API Key 引用，不能新建或切换模型配置，写作规范库也显示不可用。异常发生在旧配置迁移和写作规范 API 访问之前，现有证据不支持“八套配置或规范数据库已经损坏”的结论。

当前安装器在候选 Adapter 完整导入和健康检查之前就覆盖三宿主插件与 Adapter，并把运行数据暂时搬出再放回程序目录；同时还会修改系统或用户 Python 依赖。候选失败后可能留下新版插件、死亡 Adapter、不可追踪依赖和旧运行数据的混合状态，无法作为可靠的事务式升级或回退机制。

与此同时，现有 Word 文档审查主要面向限量文本。用户处理日常不超过 60,000 审查字符、极端不超过 120,000 审查字符的 Word 文档时，无法通过一次操作获得覆盖全文审查范围的最终报告。40k 上下文窗口不能安全承载 120,000 个中文字符、系统提示词、结构信息和输出空间；即使模型或工作流平台拥有更大上下文，仍受到显式平台限制、最大输出、成本、延迟、严格结构输出和问题枚举饱和约束。因此，一次性全篇审查必须是一项用户任务，而不是一次模型请求。

此外，现有 Word 格式审查仍以有限属性和局部模型判断为主，无法证明全篇格式覆盖，也没有把确定性格式规则、模糊角色语义、题注关系、缺失图题/表题建议和不支持对象清晰分层。已经获得授权的 `wx-doc-format-skill` 确定性算法需要在不引入运行时外部仓库依赖、不采用其默认模板值、不恢复自动排版写回的前提下纳入 AI-WPS。格式审查需要覆盖日常 60,000 审查字符以内、极端 120,000 审查字符的 Word 文档，并将模型严格限制在确定性规则无法解决的角色、关系和只读题注建议。

当前三宿主界面也存在可观察的不一致：Word 设置页的结构、按钮几何和高亮状态与 Excel/PPT 设置页不统一；智能编写等任务页的模型配置下拉在模型直连时额外显示模型标识，信息过载且三端格式漂移；Excel 的智能分析与公式助手实际复用同一 Ribbon PNG，PPT 的智能总结与结构审查也实际复用同一 Ribbon PNG，无法通过图标区分功能。

这些工作必须统一规划，但现场恢复不能等待大型新功能完成。需要先形成可以独立安装、验证和追踪的恢复构建，再在该基线上交付全篇审查、确定性优先格式审查及三宿主体验修正的整合版本。

## Solution

采用两个连续且独立验收的交付节点。

第一节点发布 `v0.23.1-alpha` 恢复构建：修复 Python 3.8 导入错误；建立真实 Python 3.8 目标运行时门禁；重做安装、数据迁移、健康状态、诊断、备份、回退和交付包结构。候选程序、三宿主插件、发布私有依赖和运行数据副本必须先隔离验证，业务就绪后才切换当前发布代际。核心数据异常时 Adapter 保持可达并进入恢复模式；仅写作规范等增强子系统异常时进入降级状态，核心任务继续执行且明确披露规范未完整应用。

第二节点发布 `v0.24.0-alpha` 整合版本：必须建立在已经完成麒麟 V10、目标 WPS 和 `cloud` 用户现场验收的 `v0.23.1-alpha` 基线上。该版本为 Word 增加模型直连“全篇审查”；同时将格式审查重构为基于格式审查快照和格式语义模型的确定性优先全篇只读审查，内置已经授权的确定性算法，只把模糊格式候选交给受限模型语义操作。图像语义实现随包休眠交付且默认关闭，后续目标环境验证完成后可通过运行时总开关、图片外发授权和模型配置视觉能力验证显式启用。整合版本还统一 Word 设置页与 Excel/PPT 的紧凑界面基线，精简三宿主任务页模型配置标签，并用许可明确的不同图标替换 Excel/PPT 重复 Ribbon 资源。

`v0.23.1-alpha` 不等待全篇审查实现或验收；`v0.24.0-alpha` 不得绕过恢复构建的目标机验收。Issue #25 统一追踪两项工作，但交付证据、版本身份和验收状态必须分开。

## Implementation Decisions

- 两项工作在同一规划和开发主线上推进，但设置两个不可合并的交付节点：`v0.23.1-alpha` 恢复构建先行，`v0.24.0-alpha` 全篇审查整合版本后续交付。
- `v0.23.1-alpha` 不等待全篇审查；`v0.24.0-alpha` 以已完成麒麟 V10/WPS 目标机验收的恢复构建为阻断前置条件。
- 不重新发布或覆盖同名 `v0.23.0-alpha`，两个新版本分别保留安装包、日志、验收和回退证据。
- 当前现场根因确定为 Python 3.8 在应用导入时执行 `tuple[...]` 类型注解并抛错；修复必须使用 Python 3.8 兼容类型表达，并扫描其他生产代码兼容风险。
- 真实 Python 3.8 对最终交付包的完整导入和实际启动是阻断式目标运行时门禁；语法编译、静态扫描和 Python 3.9 以上测试不能替代。
- 最终交付包必须在 Python 3.8 启动 Uvicorn，校验版本、健康契约和关键配置接口，并覆盖全新安装、旧版升级、故障注入和回退。
- 自动化门禁通过后只能标记为候选构建；只有麒麟 V10、目标 WPS 和 `cloud` 用户真实升级验收后才能标记为已验收恢复构建。
- 安装器在写入前校验目标安装主体。默认要求当前 WPS 登录用户以非 root、非 sudo 方式安装；管理员代装必须显式指定目标用户并验证 UID、主目录和 WPS 插件目录。
- 插件、Adapter 和运行数据目录必须属于同一目标 UID 且可写；校验失败保持原状态并停止，不得静默递归修改属主。
- 切换前要求 WPS、ET 和 WPP 全部退出，否则不写入任何发布组件。
- 候选三宿主插件、发布清单、Adapter、发布私有依赖和运行数据副本先在隔离位置验证；业务就绪后才切换当前发布代际。
- 三宿主插件、`publish.xml`、Adapter 程序、自启动或当前版本指针、发布私有依赖及匹配运行数据快照组成同一发布代际，必须整体验证、切换和回退。
- 跨目录切换使用持久化事务日志、同文件系统重命名和反向补偿；不宣称跨目录绝对原子。安装中断后，本次或下次运行必须恢复完整上一代际。
- 安装根目录分为不可变版本目录、当前代际指针、正式运行状态、已校验备份以及日志/PID/事务记录。程序版本目录安装后不得被运行时修改。
- 配置、八类任务映射、激活关系、API Key 文件和写作规范数据库只保存在正式运行状态目录；日志、PID 和事务记录不进入运行数据快照。
- Python 依赖按发布代际隔离，使用经过校验的离线 Wheel 安装到版本私有目录。候选预检和正式启动使用同一目录，并禁止加载用户 site-packages；安装不得修改系统或用户 Python 环境。
- 旧布局迁移采用写时复制：先生成脱敏清单和校验信息，在副本上迁移和验证，全部通过后才原子切换正式运行状态。
- 模型配置迁移验证八类任务数量、服务地址、Key 引用和激活关系；规范库迁移验证结构、条目数量、启用状态和数据库完整性。
- API Key 只检查存在性和不可逆指纹；安装、迁移、诊断、验收及审计日志不得输出明文。
- 模型配置、任务映射、激活关系、Key 文件和规范库数据库形成同一一致性运行数据快照，默认不允许局部恢复单个文件。
- 每次安装、迁移和显式恢复前创建快照；快照必须在副本完成结构、引用和数据库完整性验证后整体原子恢复。
- 快照目录权限为 `0700`，敏感文件为 `0600`。至少保留最近三个已校验快照和上一已验收版本的最后有效快照；唯一有效或仍承担回退作用的快照不得按时间自动删除。
- 数据恢复要求显式备份 ID、二次确认和脱敏审计记录；不得隐式选择备份、用空数据重置或以局部恢复代替一致性恢复。
- 健康契约分为 `/health/live`、`/health/ready` 和兼容聚合 `/health`。存活接口不读取业务数据；就绪接口检查核心必需子系统；聚合接口返回脱敏子系统状态。
- 聚合状态为 `ready`、`degraded` 或 `recovery`。仅写作规范等非核心增强子系统失败时为 `degraded`，业务就绪返回 200，Word 任务按规范降级继续；模型配置或任务路由等核心数据失败时为 `recovery`，业务就绪返回 503。
- 三种聚合状态下存活接口和聚合接口均返回 HTTP 200。子系统只返回稳定状态、错误码、发生阶段和允许动作，不返回 Key、配置正文或敏感绝对路径。
- 恢复候选不得自动切换。当前版本也不就绪、原数据备份校验通过且候选存活并明确处于恢复模式时，才允许显式激活恢复模式；该结果不得标记为升级成功。
- `v0.23.1-alpha` 的降级前端保持正常子系统可用，规范管理只读，并在 Word 任务提交和结果区提示规范未完整应用。
- `v0.23.1-alpha` 的恢复前端只允许重新检测、创建只读备份和导出脱敏诊断，禁止配置变更和模型任务；不提供一键重置或一键图形化恢复。
- 脱敏诊断包只包含版本、运行时、阶段、稳定错误码、子系统状态、数量、不可逆指纹和清洗日志，不包含正文、配置正文、密钥或敏感路径。
- 从 `v0.23.1-alpha` 起使用白名单交付构建，重新组装安装器、三宿主插件、Adapter、目标 Wheel、清单、诊断/验收/恢复脚本、必要文档和许可证。
- 交付包排除旧版本归档、测试和开发脚本、缓存临时文件、现场运行数据、被正式入口替代的 standalone 或兼容启动残留、非目标架构或运行时依赖及未被清单引用的材料。
- 交付构建执行允许列表、文件哈希、依赖引用闭包和敏感信息审计。清理只作用于交付产物，不直接删除源码仓库历史设计、测试和追溯材料。
- “一次性全篇审查”定义为一次用户任务和一份最终报告，不是一次模型请求。
- `v0.24.0-alpha` 首版全篇审查只支持模型直连和 OpenAI-compatible Chat Completions 核心协议；工作流平台继续使用现有限量审查。
- DeepSeek v4 flash 原生上下文为 1M，Dify 平台限制为 128k；工作流模型节点 2,048 max token 是最大输出而不是上下文窗口。
- 全篇审查使用独立公开 Adapter 协议，覆盖抽取会话创建、批次上传、快照提交、任务创建、状态、取消、分页问题、报告、导出和删除；现有限量接口保持兼容。
- 全文审查范围包含正文段落、标题、项目符号和编号正文、正文可读字段显示结果及保留行列和合并关系的正文表格。
- 页眉页脚、脚注尾注、批注与修订历史、文本框和形状、图片 OCR、公式图表、嵌入附件及隐藏文字不在首版范围；报告必须量化覆盖并披露未审查区域。
- 审查字符数只统计范围内去重后的正文和表格可见字符，不等同于 Word 状态栏字数、文件大小或 Token。
- 容量分级为：不超过 20,000 使用单分片且跳过全局汇总；20,001–60,000 自动进入标准全篇流程；60,001–120,000 在完整快照后要求用户确认；超过 120,000 明确拒绝。
- 单任务模型调用硬上限分别为 8、16 和 24 次，包含正常分片、网络重试、格式纠正、自适应子分片和全局汇总；恢复任务不重置计数。
- WPS 只读取内容块类型、顺序、段落文本、标题层级、列表标签、原文位置，以及表格行列、单元格文本、合并和嵌套关系，不采集格式审查属性或重复保存全文。
- WPS 使用约 2,000–4,000 审查字符的自适应批次，每批后让出任务窗格线程，并检查取消、会话和编辑信号。超长段落或单元格按句子和字符继续拆分且保留偏移。
- 抽取采用两遍轻量一致性验证：首遍暂存内容、统计和滚动哈希，次遍重新读取文本与结构摘要；内容块数量、字符数、区域统计和完整哈希一致且提交前无编辑事件时才冻结快照。
- 两遍抽取在目标机的性能目标为 60,000 审查字符 30 秒内、120,000 审查字符 60 秒内；这是抽取目标，不是包含模型调用的端到端完成时间。
- 暂存协议返回公开会话 ID 和至少 256 位随机强度的秘密上传令牌；Adapter 只保存令牌哈希。上传验证连续序号、范围、哈希、幂等、请求体和累计字符上限。

- 模型标识仍是直连配置的运行参数，并继续在设置页配置详情和编辑子页展示；下拉精简不改变 Adapter API、完整度或任务执行基线。
- Excel 智能分析保留现有图标，公式助手采用 Fluent System Icons `Math Formula 32 Regular`；PPT 智能总结保留现有图标，结构审查采用 `Slide Text Multiple 32 Regular`。
- 两个上游 SVG 转换为透明 32×32 本地 PNG，并进入各宿主 `GetImage` 独立映射；目标机运行时不联网加载，也不新增运行时依赖。
- 图标来源使用 Microsoft Fluent System Icons MIT 许可；交付记录精确资产、版本或提交、来源 URL、原始和派生哈希、本地变换、版权和许可证，并纳入白名单及引用闭包审计。

## Testing Decisions

- 测试只验证可观察外部行为、协议契约、文件系统结果和数据生命周期，不锁定私有函数、内部类或临时实现细节。
- 最高层测试接缝统一为“最终白名单交付包的三宿主行为契约”：同一最终产物覆盖升级生命周期、公开 Adapter API、正式 WPS 插件资源与行为及目标机验收；下列 API、Node 和真机测试是该接缝的分层实现，不建立彼此冲突的第二套产品契约。
- 第一最高层接缝是最终交付包升级生命周期：使用最终白名单交付产物、真实 Python 3.8、隔离用户目录和可控端口，执行安装前状态构造、候选预检、发布代际切换、HTTP 验证、故障注入、补偿回退和重启检查。
- 升级生命周期复用现有打包测试、安装脚本和交付冒烟测试的组织方式，但新增覆盖整个最终产物的单一生命周期测试入口。
- 升级夹具覆盖全新安装、带八类任务配置/Key 引用/激活关系/规范库的 `v0.22.0-alpha` 升级，以及当前程序已损坏但运行数据尚未迁移的 `v0.23.0-alpha` 现场状态。
- 升级生命周期注入 Python 导入失败、候选启动失败、健康版本错误、核心数据迁移失败、规范数据库失败、目录归属不一致、WPS 进程未退出和安装进程中断。
- 测试证明核心迁移失败保持原数据并进入恢复路径，规范数据失败进入降级且 Word 核心任务继续，不可导入候选不切换，安装中断可以恢复完整上一发布代际。
- 测试校验发布私有依赖不修改系统或用户 site-packages，候选预检和正式运行加载同一依赖集合。
- 测试校验一致性运行数据快照的清单、权限、引用、原子恢复、最小保留和唯一有效快照保护。
- 测试校验 `/health/live`、`/health/ready` 和 `/health` 的 `ready/degraded/recovery` 状态、HTTP 状态码、子系统错误码和敏感字段缺失。
- 测试校验恢复激活需要当前版本不就绪、已验证备份、候选存活与显式参数，并确保结果不标记为升级成功。
- 测试校验交付包白名单、哈希、依赖引用闭包、版本一致性和敏感信息扫描，不把源码仓库历史清理作为交付验收条件。
- 第二最高层接缝是全篇审查公开 Adapter API 端到端：使用真实任务协调器、假模型提供方、可控时钟和隔离临时存储，从会话创建、批次上传和快照提交执行到分页结果、导出、取消、恢复和清理。
- 全篇 API 测试复用现有文档审查、模型直连、长任务协调器、跨宿主长任务和写作规范服务的测试模式与夹具。
- 自动化覆盖审查字符计数、Token 预算、容量分级、标题/段落/句子/字符/表格分片、重叠覆盖、锚点、问题身份和去重。
- 自动化覆盖严格 Schema、一次格式纠正、输出饱和、两层自适应拆分和 8/16/24 次调用硬上限。
- 自动化覆盖秘密上传令牌、序号、哈希、幂等、乱序、重放、缺失批次、跨任务写入、请求上限和路径安全。
- 自动化覆盖十分钟部分抽取清理、三十分钟确认超时、两小时恢复、二十四小时结果保留、完成即清理和主动删除。
- 自动化覆盖 Key 指纹恢复、Key 轮换拒绝、Adapter 重启、有限重试、已完成分片不重复调用和相同活跃任务复用。
- 自动化覆盖多个全篇任务的分片级公平调度，以及智能编写等交互任务优先获得下一空闲槽。
- 自动化覆盖功能开关关闭时不创建暂存数据，启用条件不足时不调用模型。
- 第三接缝是 WPS 正式插件契约：复用三宿主设置页、写作规范、长任务和任务窗格体验的 Node 测试，验证健康状态呈现、权限边界、两遍轻量抽取、进度取消、编辑中止、轮询恢复、分页状态和保守定位。
- 插件契约证明 `degraded` 与 `recovery` 不被误报为无法连接，恢复模式不暴露变更入口，规范降级提示同时出现在提交前和结果区。
- 插件契约证明全篇抽取只读取首版需要的轻量属性，不调用正文、表格或格式写入属性。
- 第四接缝是麒麟 V10、目标 WPS 和 `cloud` 用户真机验收；自动化候选门禁不能替代该接缝。
- `v0.23.1-alpha` 真机验收覆盖 Adapter 持续监听 18100、WPS 重连、八类配置/地址/Key 引用/激活关系保持、配置新建保存切换、规范库数量/启用状态/更新时间、WPS 与 Adapter 重启保持和脱敏日志。
- `v0.24.0-alpha` 真机验收覆盖 60,000 与 120,000 审查字符、大量短段、超长段、普通/合并/跨页/嵌套/大型表格、抽取响应性、编辑中止、取消、关闭 WPS、Adapter 重启、网络异常、Key 轮换、公平调度、分页、导出和过期。
- 真机验收比对审查前后的 Word 正文和表格摘要，证明全链路只读。
- 60,000 字符 30 秒和 120,000 字符 60 秒只验收两遍轻量抽取，不作为包含模型调用的端到端完成时限。
- 验收证明审查覆盖完整性，不把“模型检出全部问题”设置为可自动证明条件。
- 格式审查 API 端到端复用全篇审查的秘密会话、连续批次、隔离存储、可控时钟和共享任务协调器夹具，但使用独立格式快照 Schema；从创建、批次上传、两遍指纹提交执行到规则、语义、分页报告、取消和清理。
- 格式规则测试以格式语义模型和编译规则包为最高确定性接缝，验证相同事实产生稳定结论，不针对内置第三方分支的私有函数逐一复制测试。
- 授权算法适配测试使用上游黄金案例和 AI-WPS 反例，覆盖标题/列表/表格/题注识别、正向数据表证据以及第三方默认模板值不得进入权威规则包。
- 自动化覆盖全文与选区语义扩展、范围外上下文不产出问题、未执行全局规则、页眉页脚尽力读取和不支持对象清单。
- 自动化覆盖两遍结构/格式指纹、纯格式编辑中止、混合字符区段二分、相邻合并、碎片上限和对象复杂度拒绝。
- 自动化覆盖角色证据组合、样式自证循环反例、证据冲突、0.85 生效门槛、未知角色、未配置映射和正文回退禁令。
- 自动化覆盖表格语义正向证据、排版表/说明框反例、题注有限候选边、关联与位置分离、重复/歧义题注和对象缺题注无法判定。
- 模型语义契约使用假工作流和假直连 Provider，覆盖四类操作白名单、快照绑定、候选目标、8,192 输入、2,048/4,096 输出、16 次总量、60 秒单调度和 10 分钟阶段时限。
- 自动化覆盖一次瞬时重试、一次 Schema 纠正、整批无效响应拒绝、必需/可选语义优先级、串行调用、批次让位、公平调度和取消后在途结果丢弃。
- 自动化覆盖 `format_semantics.v1` 的固定输入和 `result_json` 输出、旧工作流保留、未验证时确定性降级、文本/视觉参考 DSL 的 2,048 输出和安装器不自动导入。
- 表题建议测试覆盖完整证据和首三末二受限证据、证据状态、80 字题注正文、编号分离、证据外机构/时间/地域/数值/口径拒绝及证据不足不生成。
- 视觉默认关闭测试从最终产物证明升级后总开关为 `false`，不创建槽位、不调用 `SaveAsPicture`、不上传像素、不标记 `pixel_inspected`，同时仍执行图片确定性规则和文字证据降级。
- 图像槽位安全测试覆盖任意路径、路径穿越、符号链接、非普通文件、错误属主、伪 PNG、哈希变化、尺寸与大小门禁以及全部终态清理。
- 图像批次测试覆盖单图 5 MiB/8,192/2,000 万边界、同组 1–4 图、第五张拒绝、组内单图失败全组降级、只外发缺图题候选、预算耗尽和逐组立即删除。
- 图像一致性测试使用可控 WPS 适配器验证导出前后指纹、任何编辑停止剩余导出、关闭文档/任务窗格/Adapter 重启降级、原文和对象属性不写入。
- 图片外发授权测试覆盖总开关、配置级授权、主机/模式/模型变更失效、合成视觉探针、本次任务关闭和报告不含图片、本地路径、Key 或远端删除承诺。
- 受限内网条件下，当前候选发布测试只要求休眠视觉代码和关闭行为完整；真实 `SaveAsPicture` 视觉保真度不作为本次发布门禁，但在管理员后续开启前必须另行记录目标 WPS 验收通过。
- 三宿主设置页复用现有 workflow settings 契约测试，新增结构角色、控件高度/圆角 token、主次/危险/选中/焦点/禁用状态、窄窗折行和 Word 写作规范卡保留断言。
- 三宿主任务页下拉测试统一断言可用配置显示为 `配置名称 · 接入方式`，模型标识、地址、Key、备注、激活符号均不出现，同时保留稳定 option 节点复用和快速切换回归。
- Ribbon 资源测试从最终插件读取 `GetImage` 映射，证明 Excel 两个业务按钮和 PPT 两个业务按钮分别引用不同文件；新资源为透明 32×32 PNG，哈希不同于旧共享图标。
- 交付审计测试把 Fluent 上游资产、版本或提交、许可证、版权、原始/派生哈希和本地变换纳入第三方声明、白名单和引用闭包，并证明目标机无网络资源依赖。
- 麒麟真机 UI 验收覆盖 Word/Excel/PPT 设置页在常规和窄任务窗格中的按钮、高亮、焦点和禁用状态，任务下拉标签，以及 Excel/PPT Ribbon 在普通和高 DPI 下的图标辨识度。

## Out of Scope

- 在 `v0.23.1-alpha` 中实现或等待全篇文档审查。
- 重新使用 `v0.23.0-alpha` 版本号覆盖故障包。
- 在恢复构建中提供一键重置、一键图形化恢复或自动选择备份。
- 把 `degraded` 或显式激活的 `recovery` 状态标记为已验收恢复构建。
- 自动递归修改目标目录属主，或通过 root 的 HOME 隐式决定目标用户。
- 继续向系统或用户 site-packages 安装运行依赖。
- 删除源码仓库中的历史设计、测试、ADR 或追溯材料。
- 要求 standalone 或其他历史兼容启动入口进入正式交付包。
- 工作流平台的全篇审查协议和专用分片、汇总工作流。
- 使用一次模型请求承载 60,000 或 120,000 审查字符全文。
- 超过 120,000 审查字符的首版全篇任务。
- 页眉页脚、脚注尾注、批注修订、文本框形状、OCR、公式图表、附件和隐藏文字审查。
- 自动写回 Word 正文、表格、批注或修订。
- DOCX 报告导出、流式输出、工具调用和厂商原生模型协议。
- 云端持久化审查历史、跨设备同步和多人协作状态。
- 保证模型发现全部问题。
- 自动套用、修复或写回格式审查结论；首版格式审查和题注生成均只提供结构化问题与建议。
- 把第三方项目的默认模板值、默认样式名或厂商分支直接作为 AI-WPS 规则权威来源。
- 使用模型替代可确定的格式规则、让模型自由发现候选对象，或让模型自行分类表格语义类型。
- 对文本框、形状、SmartArt、公式内部、脚注尾注、批注、修订历史、隐藏文字、图表、OLE/ActiveX 或水印执行首版内部格式/视觉审查。
- 新安装或升级后默认开启图片语义能力，或在目标 WPS 真机验收完成前宣传图片内容已经被模型检查。
- 使用 Pillow、直接提取 OpenXML 原图、上传原文件名、自动缩放/压缩超限图片或发送不完整的多图对象组。
- 承诺远端模型或工作流平台已删除图片；AI-WPS 只保证本机受控临时资产按生命周期清理。
- 在任务页模型配置下拉中展示模型标识；模型标识仍保留在直连配置详情和编辑界面。
- 改变三宿主既有配置 API、配置完整度、激活关系、恢复模式、写作规范管理或任务执行语义。
- 在目标机运行时联网下载 Ribbon 图标，或为两个静态 PNG 新增运行时依赖。
- 为交付重整进行与本规格无关的大规模业务代码重构。

## Further Notes

- Issue #25 被本规格覆盖后同时追踪恢复构建和全篇审查，但实现必须按版本节点拆分，`v0.23.1-alpha` 可以且必须独立完成。
- 本次现场的三个界面症状共享 Adapter 导入崩溃这一上游根因，置信度为高；旧配置和规范数据是否完整仍需由恢复候选的只读清单、迁移验证和真机验收确认。
- 40k 上下文的核心限制是系统提示词、正文、结构元数据和输出预算的总 Token；中文字符到 Token 的比例必须使用目标模型实测校准。
- 120,000 审查字符是极端场景，日常目标集中在 60,000 以内，但极端场景仍必须具备明确门禁、调用上限和目标机验收。
- 工作流平台拥有 128k 上下文不等于自动具备全篇协议；2,048 最大输出还会提高长问题列表饱和风险。
- 全局汇总只能检查已经进入分片摘要、受控事实和问题索引的跨分片信息，不能补救分片阶段完全遗漏的内容。
- 格式审查确定性算法依据已获作者授权的本地 `wx-doc-format-skill` v0.12.15 源码适配；AI-WPS 自身格式规则包、协议、生命周期和测试仍是产品行为的唯一权威。
- 当前内网测试条件不足，因此视觉实现随版本休眠交付、总开关默认关闭且不设置本次发布真机门禁；未来开启前必须补齐指定 WPS 环境的 `SaveAsPicture`、资源安全、文档不变性和多图原子性验收。
- Ribbon 替换资源取自 Microsoft Fluent System Icons：Excel 公式助手使用 `Math Formula 32 Regular`，PPT 结构审查使用 `Slide Text Multiple 32 Regular`；两者按 MIT 许可证转制为本地透明 PNG，并保留来源、版本、哈希和许可证追溯。
- 相关架构决策为 ADR-0032 至 ADR-0113：ADR-0050 明确两个交付节点，ADR-0051 至 ADR-0065 定义恢复构建、升级、状态、数据、依赖和交付包边界，ADR-0066 至 ADR-0110 定义确定性格式审查、模型语义和休眠视觉能力，ADR-0111 至 ADR-0113 定义三宿主 UI、选择器标签和 Ribbon 资源边界。
- 规格和测试接缝已经完成共同理解确认；最高测试接缝是最终白名单交付包的三宿主行为契约，API、Node 契约和真机验收是其分层实现。发布仍必须通过相应自动化门禁；视觉能力只有在后续显式启用前才要求完成专项真机验收。
