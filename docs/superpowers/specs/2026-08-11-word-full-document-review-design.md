# Word 模型直连全篇文档审查设计

日期：2026-08-11

状态：已确认

适用项目：AI-WPS `v0.23.0-alpha` 后续版本

适用任务：`word.document_review`

## 1. 结论

40k 上下文的模型直连不能通过一次模型请求完整审查十二万字 Word 文档。首版将“一次性全篇审查”定义为用户发起一次全篇任务，由 WPS 分批抽取正文与表格，本地 Adapter 形成可验证快照，再按模型预算顺序执行多个语义分片调用，最后基于可追溯事实索引完成全局一致性汇总。

模型直连的默认 40k 配置按 8k 输出预留和 10% 安全余量计算，可用输入预算为 28k Token。现有 System Prompt、任务指令和最多 3,000 字符写作规范占用后，中文正文理论上限约为 2.38 万至 2.69 万字；首版采用单片目标 18,000 字、硬上限 20,000 字、相邻上下文重叠 500 至 1,000 字。

日常六万字以内文档预计使用三至四个审查分片，另加一次全局汇总；十二万字极端文档预计使用七至八个审查分片，另加一次全局汇总。输出饱和、有限自动重试和自适应拆分会增加调用，但受单任务硬上限约束。

## 2. 目标与非目标

### 2.1 目标

- 一次用户发起即可处理首版全文审查范围，不要求用户手动分段。
- 证明目标正文没有被静默截断，并区分正文覆盖完整性与模型问题枚举完整性。
- 支持六万字以内日常文档和十二万字以内极端文档。
- 保持模型输入预算、结果定位、失败恢复、费用上界和共享调度可验证。
- 保持现有文档审查只读，不自动修改 Word。
- 保持现有限量审查接口和工作流平台行为兼容。

### 2.2 非目标

- 不承诺模型检出全部问题。
- 不在一次模型请求中提交六万或十二万字全文。
- 首版不审查页眉页脚、脚注尾注、批注修订、文本框形状、图片 OCR、公式图表、嵌入附件或隐藏文字。
- 首版不为工作流平台提供全篇长文档审查。
- 不自动替换正文或表格，不批量应用模型建议。
- 首版不生成 DOCX 审查报告。

## 3. 产品容量边界

产品以“审查字符数”分级。审查字符数只统计首版全文审查范围内去重后的正文与表格可见字符，不统计 Word 控制符、分片重叠、重复表头、Adapter 锚点或模型提示词。

| 审查字符数 | 行为 | 基础调用估算 | 单任务调用硬上限 |
| --- | --- | ---: | ---: |
| 不超过 20,000 | 单分片审查，不调用全局汇总 | 1 | 8 |
| 20,001 至 60,000 | 标准全篇审查，自动进入模型队列 | 3 至 5 | 16 |
| 60,001 至 120,000 | 大型文档审查，本地快照完成后要求确认 | 5 至 9 | 24 |
| 超过 120,000 | 拒绝全篇提交，要求缩小范围 | 0 | 0 |

所有正常分片、网络重试、格式纠正重试、自适应子分片和全局汇总都计入调用硬上限。恢复同一任务不重置计数。

大型文档确认页显示审查字符数、初始分片数、基础调用估算和调用硬上限。用户拒绝或确认超时后删除快照，不调用模型。

## 4. 首版全文审查范围

### 4.1 纳入

- 正文普通段落和各级标题；
- 项目符号和编号正文；
- 保留行列、单元格和合并关系的正文表格；
- 正文中可读取的字段显示结果；
- 正文和表格之间的章节与逻辑关系。

### 4.2 不纳入

- 页眉和页脚；
- 脚注和尾注；
- 批注、回复和修订历史；
- 文本框、形状和 SmartArt 文字；
- 图片文字和扫描件 OCR；
- 公式、图表及嵌入附件的语义内容；
- 隐藏文字。

最终结果量化已审查段落、表格、单元格和字符数，并明确披露未审查区域，不使用“DOCX 全部内容”或“所有 Word 对象”等表述。

## 5. 总体流程

```text
用户发起全篇审查
  -> WPS 创建秘密上传会话
  -> 第一遍分批轻量抽取正文与结构化表格
  -> 第二遍轻量哈希验证
  -> Adapter 提交并冻结审查快照
  -> 容量分级与大型文档确认
  -> 生成语义审查分片
  -> 分片级公平调度和顺序模型调用
  -> 本地确定性写作规范检查
  -> 多分片时执行全局一致性汇总
  -> Adapter 验证、去重并持久化最终结构化报告
  -> WPS 分页查看、定位、处理和导出
```

## 6. WPS 轻量抽取

### 6.1 专用抽取字段

全篇文档审查不复用格式审查的完整段落属性采集，只读取：

- 内容块类型和原文顺序；
- 段落正文、标题层级、列表标签和原文位置；
- 表格、行、列、单元格文字、合并关系、嵌套层级和原文位置。

不读取字体、字号、粗体、斜体、缩进、行距、页边距等格式字段。同一正文不得同时完整复制到 `plainText`、`paragraphs` 和 `documentStructure.paragraphs`。

### 6.2 自适应时间片

- 每批目标约 2,000 至 4,000 审查字符；
- 每批完成后让出任务窗格线程；
- 根据上一批耗时动态调整下一批大小；
- 每批检查取消、会话有效性和文档编辑信号；
- 单个超长段落或单元格不截尾，按句子和字符继续拆分并保留偏移。

### 6.3 两遍一致性验证

第一遍抽取并暂存内容块、统计和滚动哈希。第二遍只重新读取文本与结构摘要，不重复上传正文；只有内容块数量、审查字符数、区域统计和完整哈希一致，且校验结束到提交之间没有编辑事件，才形成审查快照。

任一不一致都删除暂存并要求重新发起，不局部修补混合版本。快照形成后用户可以继续编辑当前文档，后台结果仍对应已冻结快照。

### 6.4 真机性能目标

| 指标 | 首版目标 |
| --- | ---: |
| 单个抽取时间片 | 通常不超过 50ms |
| 单次连续阻塞 | 不超过 200ms |
| 用户取消响应 | 1 秒内停止启动新批次 |
| 六万审查字符两遍抽取 | 30 秒内 |
| 十二万审查字符两遍抽取 | 60 秒内 |

这些目标必须在麒麟 V10 ARM、WPS 12.1.2 验证。目标机不达标时优先保持界面响应性，不通过扩大同步批次掩盖耗时。

## 7. 本地暂存协议与安全

现有限量接口保持不变。全篇审查使用独立协议，仍共用 `word.document_review` 模型配置、API Key和共享调度器。

```text
POST   /word/document-review/full/snapshots
PUT    /word/document-review/full/snapshots/{sessionId}/batches/{sequence}
POST   /word/document-review/full/snapshots/{sessionId}/commit
DELETE /word/document-review/full/snapshots/{sessionId}

POST   /word/document-review/full/jobs
GET    /word/document-review/full/jobs/{jobId}
DELETE /word/document-review/full/jobs/{jobId}

GET    /word/document-review/full/jobs/{jobId}/issues
GET    /word/document-review/full/jobs/{jobId}/report
DELETE /word/document-review/full/jobs/{jobId}/result
```

创建抽取会话时返回公开 `sessionId` 和至少 256 位随机强度的秘密 `uploadToken`。Adapter只保存令牌哈希；上传、提交和删除暂存必须验证令牌、连续批次序号、内容哈希、锚点范围、单次请求体和累计字符上限。令牌不进入日志、诊断或错误正文，并在快照提交后失效。

文件路径只使用随机标识，不使用用户文件名或正文。暂存和结果文件权限固定为 `0600`，正文、文件名或请求字段不得参与路径拼接。

### 7.1 模型调用前清理

- 部分抽取最后活动十分钟后删除，不跨 WPS 重启续接；
- 校验失败立即删除；
- 大型文档完整快照等待确认最多三十分钟；
- 用户拒绝、取消或确认超时立即删除。

## 8. 模型容量和就绪度

全篇审查只对模型直连开放。模型配置必须显式保存：

- 服务地址、API Key和模型名称；
- 上下文窗口 Token；
- 最大输出 Token；
- 现有可选温度参数。

最大输出低于 2,048 时不开放全篇审查，推荐值为 8,000。历史最大输出空值不自动迁移为 8,000；它仍可执行限量审查，但不显示为全篇审查可用。每次分片和汇总请求显式发送 `max_tokens`。

设置页分别披露“限量审查可用”和“全篇审查可用”。验证调用检查显式输出上限是否被Provider接受、严格JSON契约、提示词清单和最终内容剥离推理字段。

40k、8k 输出配置的安全输入预算为：

```text
40,000 - 8,000 - 4,000（10%安全余量） = 28,000 Token
```

Adapter仍对每次实际System Prompt、用户查询和规范注入执行最终预算检查，前端字符上限不替代Token预算。

## 9. 语义分片

单片目标 18,000 字，硬上限 20,000 字，后片携带前片尾部 500 至 1,000 字作为上下文。分片边界优先级：

1. 标题和章节边界；
2. 完整段落边界；
3. 句子边界；
4. 字符边界最终兜底。

重叠区不重复计算覆盖率。模型可参考重叠区，但局部问题必须归属唯一核心区。

表格优先整体保留；超限时按完整行拆分，后续子分片重复必要表头但不重复计入覆盖。超长行按单元格拆分，单元格仍超限时按句子和字符拆分。表格锚点保留表格、行、列、合并关系和单元格内偏移。

## 10. 提示词与模型结果

全篇审查使用两份独立版本化System Prompt：

- `word-document-review-chunk.md`：局部分片问题、摘要、事实索引、跨片核对项和饱和信号；
- `word-document-review-aggregate.md`：跨章节矛盾、语义去重和最终总体结论。

两份资产独立记录版本和 SHA-256，随交付包发布，共用同一个 `word.document_review`模型配置与认证快照。单分片任务跳过全局汇总；两个及以上分片才执行汇总。

分片与汇总只接受带 `schemaVersion` 的完整严格JSON。Adapter验证Schema版本、请求与响应分片标识、字段类型与长度、锚点、事实和问题引用以及输出完整性。第一次格式错误使用固定纠正提示重试一次；再次失败进入可恢复失败。非结构化回复不进入全篇报告。

现有限量审查继续保留JSON代码块优先、普通Markdown明确降级展示的兼容行为。

## 11. 写作规范

任务提交时解析并冻结规范场景、规范包版本、组织覆盖、术语、文体、去模板化规则和注入文本哈希。每个分片使用同一规范快照，运行期间规范库变化只影响新任务。

确定性术语、别名、禁用写法和模板表达检查对完整审查快照执行一次，不按分片重复扫描；它直接生成原文锚点并与模型问题合并。语义型文体规则由分片模型判断。规范注入计入输入预算，不能为容纳正文而静默删除。

规范库异常沿用现有规范降级：模型审查继续，结果披露规范未完整应用，不误报为模型接口失败。

## 12. 全局一致性汇总

每个分片返回受限的：

- 分片摘要；
- 关键定义和术语；
- 责任主体与动作；
- 时间、数量和范围条件；
- 验收条件或判定标准；
- 跨章节引用和待核对陈述。

全局模型只接收标题结构、分片摘要、事实ID、跨章节核对项和压缩问题索引，不重新接收全文或完整建议改写。它负责跨章节矛盾、语义重复、严重程度排序和总体结论；无法引用输入问题ID、事实ID或锚点的定位由Adapter拒绝。

## 13. 输出饱和与调用预算

以下任一情况认定输出饱和：

- Provider返回长度结束信号；
- JSON尾部截断；
- `hasMoreIssues=true`；
- 问题数量达到分片约定上限。

饱和分片按语义边界拆成约 9,000 字的子分片，仍饱和时可再拆到约 4,500 字，最多递归两层。父分片结果作废，以最终子分片结果合并。

最小分片仍饱和或调用硬上限到达时：

- 所有核心范围都有合法结果：`coverageStatus=complete`、`enumerationStatus=limited`，明确列出受限范围；
- 任一核心范围没有合法结果：不生成全篇报告，进入可恢复失败。

不得以“未发现其他问题”掩盖枚举受限。

## 14. 原文锚点、问题身份与去重

正文锚点由内容区域、段落号、段内字符范围和原文校验组成；表格锚点由表格、行、列、单元格和单元格内字符范围组成。模型问题必须引用当前分片中的锚点，Adapter验证锚点和必要原文片段。

当前Word文档变化后：

- 文档未变化时按原偏移定位；
- 原文在预期位置附近唯一匹配时保守重定位；
- 多处相同或无法匹配时不自动跳转，并标记定位未验证。

最终 `issueId` 由审查快照、问题类别、排序后的锚点和规范化问题语义生成。相同锚点的同一问题合并；不同位置的相同问题保留独立问题实例和处理状态，可通过 `duplicateGroupId` 分组。跨章节问题可以引用多个证据锚点。

## 15. 调度、重试与取消

同一全篇任务内部严格顺序调用，不并行发起分片请求。每完成一个分片就持久化检查点、释放共享运行槽并重新参与调度；没有其他任务时立即继续，有交互任务时沿用交互优先级和连续三次后让普通任务运行的公平规则。活跃任务等待下一片不占八个新任务排队位置。

自动重试一次只适用于连接失败、中途断开、HTTP 502/503/504和模型结构输出错误。认证、权限、模型、预算、参数和Provider 1,800秒超时不自动重试。可恢复失败保留检查点两小时，用户从失败分片继续，已完成分片不重跑。

取消行为：

- 排队、抽取、暂存和分片之间立即停止；
- 已发出的阻塞模型请求等待返回，不再启动后续分片；
- 取消后删除快照、检查点和分片结果；
- 不返回部分报告。

WPS轮询从三秒退避到十秒和三十秒，不以六十分钟作为业务失败。关闭WPS不取消任务，单次Provider调用仍使用1,800秒上限，总体由调用硬上限约束。

## 16. 持久化、恢复与认证

审查快照、分片清单、检查点和已完成分片结果受控临时落盘，权限为 `0600`，随机任务目录不包含原文件名，不保存API Key明文。

任务持久化非敏感模型参数、配置ID、Key引用和Key指纹。Adapter重启时重新读取当前Key并比较指纹，只有一致才续跑；Key删除、轮换或引用失效后，旧任务不能改用新认证继续。

生命周期：

- 完成后立即删除全文快照、分片中间结果和事实索引；
- 可恢复失败或中断保留两小时；
- 完成的最终结构化报告保留二十四小时；
- 用户取消、不可恢复失败或主动删除立即清理；
- Adapter启动扫描和周期清理过期、损坏或无法验证的数据。

## 17. 重复任务

任务身份由快照完整哈希、文档类型、审查重点、规范快照、模型配置、System Prompt版本和分片策略版本组成。

- 相同身份的等待确认、排队、运行或可恢复失败任务返回原任务号；
- 二十四小时内存在相同完成报告时先提示查看；
- 只有用户明确选择重新审查才创建新任务；
- 快照哈希不同视为新的文档版本。

## 18. 结果接口与任务窗格

终态查询只返回摘要、覆盖状态、枚举状态和问题统计，不返回完整问题数组。问题通过独立接口按稳定 `issueId` 分页读取，默认每页二十项，支持严重程度、类别、章节或表格、处理状态筛选，以及严重程度或原文顺序排序。

进度按阶段展示：读取正文、校验快照、等待大型文档确认、首次排队、分片审查、等待下一分片调度、自动重试、自适应拆分、全局汇总和完成。分片审查百分比使用已完成唯一核心区字符数除以总审查字符数，不使用动态分片数量。

任务窗格允许定位、复制建议、标记已处理或已忽略、分组查看和导出，不自动修改正文或表格。处理状态以稳定 `issueId` 为键，不使用数组下标。

## 19. 报告导出

首版支持：

- Markdown：面向人工阅读、复制到Word和归档；
- 版本化JSON：保留稳定问题ID、分组、锚点、结构化字段、处理状态和覆盖元数据。

报告不包含全文快照、分片事实、模型原始回复、API Key、Key指纹、本地临时路径或未脱敏错误正文。首版不生成DOCX。

## 20. 工作流平台边界

当前工作流平台中的 DeepSeek v4 flash 原生上下文为 1M，Dify 限制为 128k，模型节点 `max token=2048` 是最大输出而非上下文窗口。现有 12,000 字限量审查可以继续，但 2,048 输出更容易造成问题列表饱和。

首版工作流平台不进入全篇协议，原因是现有自定义System Prompt、输出上限、分片事实索引、全局汇总和完整诊断未形成专用工作流契约。后续必须发布独立分片工作流和契约测试，不能把现有应用直接表述为全篇能力。

## 21. 发布门禁

首版通过环境开关默认关闭：

```text
AI_WPS_ENABLE_FULL_DOCUMENT_REVIEW=1
```

未启用时现有限量审查不变，全篇入口隐藏，新接口返回明确未启用错误，不创建暂存目录或恢复任务。启用后还必须满足模型直连、显式 Token 容量、输出至少 2,048、提示词清单、暂存权限和严格 Schema 验证。

麒麟V10真机验收通过后，在后续版本默认开放，同时保留管理员关闭能力。

## 22. 测试与验收

### 22.1 Adapter自动化

- 字符计数、Token预算和容量分级；
- 标题、段落、句子、字符和表格分片；
- 重叠覆盖、锚点、问题身份和去重；
- 严格Schema、格式纠正、输出饱和和两层拆分；
- 8/16/24调用上限；
- 暂存Token、序号、哈希、请求体和路径安全；
- 十分钟、三十分钟、两小时和二十四小时清理；
- Key指纹恢复和轮换拒绝；
- 分片级公平调度、取消和断点续跑；
- 分页、筛选、报告生成和主动删除；
- FastAPI与standalone行为一致。

### 22.2 WPS自动化契约

- 轻量字段读取，不访问写入属性；
- 自适应批次、进度、取消和编辑中止；
- 两遍哈希校验；
- 大型文档确认；
- 轮询退避和重开恢复；
- 分页、稳定问题状态和保守定位；
- 无正文和表格写回路径。

### 22.3 麒麟V10真机

- 六万、十二万字符正文；
- 大量短段、超长段落；
- 普通、合并、跨页、嵌套和大型表格；
- 抽取性能和任务窗格响应性；
- 抽取中编辑、取消、关闭WPS；
- Adapter重启、网络异常、Key轮换；
- 两个全篇任务与交互任务公平调度；
- 结果分页、导出和过期；
- Word正文和表格前后摘要一致，证明全链路只读。

## 23. 相关架构决策

- ADR-0032：先分批暂存，再由Adapter生成模型分片；
- ADR-0033：受控临时落盘和恢复/结果保留；
- ADR-0034：基于可追溯分片事实执行全局汇总；
- ADR-0035：问题使用可验证原文锚点；
- ADR-0036：首版全文范围限制为正文与结构化表格；
- ADR-0037：首版全篇长文档只支持模型直连；
- ADR-0038：问题按稳定ID分页读取；
- ADR-0039：分片之间让出共享运行槽；
- ADR-0040：问题按原文发生位置建立稳定身份；
- ADR-0041：按处理阶段维护独立版本化提示词；
- ADR-0042：全篇阶段只接受版本化严格JSON；
- ADR-0043：全篇审查要求显式Token容量；
- ADR-0044：任务不受任务窗格六十分钟等待上限约束；
- ADR-0045：只有Key指纹一致才跨重启续跑；
- ADR-0046：暂存写操作使用秘密上传令牌；
- ADR-0047：全篇协议与限量审查协议分离；
- ADR-0048：通过两遍轻量内容哈希验证快照；
- ADR-0049：相同活跃任务按输入身份复用。
