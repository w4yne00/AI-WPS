# v0.25.1-alpha 格式审查规范化事实、技术文档模板规则、位置定位与 D-0001 修复规格

## Problem Statement

用户在目标 WPS 中使用格式审查时，即使文档实际符合标准，结果仍会把 WPS 原始纸张枚举、point 长度、行距点值和浮点噪声当作可直接比较的模板值，产生页面、段落和行距误报，并在“当前值”中显示 `7`、`89.8499998474`、`0.0625 倍`等无法理解的字符。主入口仍使用旧同步审查链，普通段落问题没有经过原文锚点富化，因此已经读取到段落序号的结果仍显示“位置未确认”。

当前活动规则仍以旧模板身份发布，不能准确表达用户已经确认的主规则来源和规则准入边界。纸张和页边距容易受宿主布局环境影响，不应继续作为合规规则；格式值、输入文档结构规则和转换器成品合同也必须分开，避免把 `wx-doc-format` 的转换行为误当成待审查文档标准。

独立的本地 DOCX 抽取缺陷 D-0001 会把 `w:pStyle/@w:val` 的数字 `styleId` 当作样式名，导致标题全部被压平。修复需要读取 `styles.xml` 和 `outlineLvl`，同时会扩大不可信 DOCX 的解析面；如果不一起补安全门禁，标题修复会引入新的 ZIP/XML 风险。

## Solution

用户从 Word 格式审查主入口提交任务后，系统统一使用确定性后台审查链生成 `format_snapshot.v2`。WPS 原始值先在采集边界转换为带来源、类型和单位的规范事实，再进入规则判定和中文展示；无法确认含义的值保持不可判定，不产生伪违规。

系统只启用显示名称为“技术文档模板规则”的主规则包。规则包使用稳定机器标识 `technical-document-template-rules`、独立规则版本 `1.0.0`，并单独记录来源版本 `wx-doc-format 0.12.15`。模板资产提供格式值，人工准入白名单提供输入文档结构规则，转换器专用合同和代码 fallback 不进入审查。纸张与四边页边距仍被正确解析并可在诊断中查看，但不产生合规问题。

结果界面、Markdown 报告和复制文本使用中文可读值，并以已验证原文锚点为身份，显示章节路径、段落序号、原文摘要以及可用的审查快照页码。文档级问题显示“全文”，节级问题显示节或章节；页码无法验证时省略，不伪造位置。

D-0001 作为独立交付单元修复：安全解析数字 `styleId`、样式名与受控继承关系，仅按确认的标准标题和 `outlineLvl` 回退边界输出 Markdown 标题，并为新增 `styles.xml` 输入面补齐恶意 DOCX 拒绝与降级测试。

## User Stories

1. As a Word 用户, I want 从唯一的格式审查入口提交任务, so that 我不会因两套审查链得到不同结果
2. As a Word 用户, I want 合规文档不再因为 WPS 原始单位而被判为违规, so that 我可以信任审查结论
3. As a Word 用户, I want `PaperSize=7` 显示为 `A4`, so that 我不需要理解 WPS 枚举码
4. As a Word 用户, I want point 长度显示为毫米、磅或适合该属性的中文单位, so that 当前值可以直接核对
5. As a Word 用户, I want 浮点噪声被确定性舍入, so that 界面不会显示 `89.8499998474` 一类机器值
6. As a Word 用户, I want 行距按多倍、固定值或最小值分别解释, so that `15pt` 不会被误算为 `0.0625 倍`
7. As a Word 用户, I want 混合格式明确显示“格式不一致”, so that 系统不会把混合值伪装成统一值
8. As a Word 用户, I want WPS 不支持的属性明确显示“当前 WPS 不支持”, so that 我能区分宿主能力限制与文档问题
9. As a Word 用户, I want 无法可靠映射的枚举显示“无法识别”, so that 系统不会猜测格式含义
10. As a Word 用户, I want 不可判定的格式事实不产生违规, so that 数据缺失不会转化为误报
11. As a Word 用户, I want 纸张和页边距不参与合规判定, so that 布局环境差异不会产生高频误报

## Implementation Decisions

- Word 格式审查主按钮统一提交确定性后台任务；旧同步审查结果链停止作为用户入口，兼容期后删除。
- WPS 采集边界建立唯一的格式事实规范化层，确定性规则、模型语义补充、报告和诊断均消费同一版格式语义模型。
- `format_snapshot.v2` 中的格式事实显式保存事实来源、原始值、原始单位、规范值、规范单位、值类型和数据状态；机器协议不使用中文字段名。
- 纸张枚举转换为语义纸型；point 到 twip 使用确定性换算和容差舍入，不通过数值大小猜测单位。
- 行距同时采集数值和行距模式，分别规范化多倍、固定值和最小值；不能再以单一阈值推断 point 或 twip。
- 混合值、未知枚举、读取失败和宿主不支持是不同的数据状态；这些状态不参与合规判定。
- 旧裸数值快照、后台任务结果和缓存不迁移到 v2，读取时明确失效并要求重新审查。
- 唯一活动规则包使用机器标识 `technical-document-template-rules`、中文显示名称“技术文档模板规则”、规则版本 `1.0.0` 和来源版本 `wx-doc-format 0.12.15`。
- wx 来源规则逐条分类为 `normative-format`、`normative-structure` 或 `converter-only`；只有前两类可以进入规则包编译白名单。
- 模板资产中的明确格式值具有最高规则优先级；人工准入的结构规则补充模板无法表达的约束；未定义属性保持未配置。
- 转换器成品合同、自动生成或写回行为、LLM 增强行为及代码 fallback 不作为输入文档审查标准。
- 纸张类型和四边页边距从合规规则中删除，但继续形成规范事实并进入诊断。
- 旧模板和规则资产转入历史区域并标记 `inactive`，从运行时注册表、交付白名单和界面移除，且不得自动回退；Git 历史和审计记录保留。
- 项目负责人确认作者已授权全量使用本地 wx 源码、模板资产和规则，不要求附加授权证据或设置证据发布门禁；规则分类与人工准入仍然适用。
- 段落问题继续以已验证原文锚点作为稳定身份，用户位置由章节路径、段落序号、原文摘要和可选快照页码组成。
- 页码只作为布局快照提示；文档编辑、宿主不支持或验证失败时省略页码，不能替代或降低已有锚点状态。
- 文档级问题显示“全文”，节级问题显示节或章节及可用页码范围，段落级问题使用最具体的已验证位置。
- 格式审查界面、Markdown 报告和复制文本使用中文可读值；原始机器值和英文错误码仅在展开诊断中显示。
- API JSON、任务快照和诊断包保持稳定机器协议；没有可靠中文映射的用户值显示“无法识别”，不得猜测。
- D-0001 在当前本地 DOCX 抽取模块中独立修复，不等待共享本地文档抽取模块落地，也不混入 ADR-0116 的无行为变化重构。
- D-0001 解析 `styles.xml` 建立数字 `styleId` 到样式名的映射，并以带环路保护的受控继承解析有效样式事实。
- 标题识别优先使用标准 Heading/标题 1–6 样式名；名称不能判定时，只允许段落直接 `outlineLvl=0…5` 作为回退。`outlineLvl=9`、负数、非数字、缺失和 6–8 不提升为标题。
- 文档标题、附录标题等组织角色不在 D-0001 中通过新启发式扩展，后续需要显式规则映射。
- 缺失 `styles.xml` 时允许使用段落直接 `outlineLvl` 降级并记录能力状态；存在但畸形、重复、超限或包含 DTD/实体时拒绝 DOCX。
- DOCX 验证覆盖条目数、总解压量、关键部件单体大小、CRC、加密、重复关键部件、不安全 OPC 路径、DTD/实体及关系和媒体资源膨胀。
- 工作拆为四个独立交付单元：事实规范化与统一入口、主规则基线、位置定位、D-0001 与恶意 DOCX 回归。前三项顺序实施，D-0001 可独立推进和验收。
- 本轮仍属于 `v0.25.1-alpha` 格式审查收敛线；旧候选构建标记为 `rejected`，新候选使用独立构建标识和日期，不改变 `v0.26.0-preview.1` 边界。

## Testing Decisions

- 格式审查的最高测试缝是“用户从 WPS 主入口提交审查，到后台任务完成并渲染最终中文报告”。测试只断言用户可观察的规范值、问题、位置、规则身份和诊断，不锁定内部 helper 调用。
- D-0001 使用独立的“暂存 DOCX 通过安全验证并抽取为结构化 Markdown 文本”外部缝，不从内部样式函数开始测试。
- 现有任务窗格契约测试、确定性格式快照协议测试、Word 格式审查服务测试、后台任务生命周期测试、本地文档文件门禁测试和 DOCX 抽取测试作为先例；已有错误宿主夹具必须修正，不能继续固化错误单位。
- 使用目标 WPS 真实契约夹具覆盖 `PaperSize=7`、`72pt`、`90pt`、`89.8499998474pt`、`LineSpacing=15pt` 及对应行距模式；断言规范化和中文展示正确，同时断言纸张和边距不生成问题。
- 覆盖多倍、固定值、最小值、混合、未知和不支持行距；不可判定状态不得被报告为合规或违规。
- 覆盖字体、字号、对齐、行距、缩进、段前段后、标题层级、列表、题注、附录等允许规则的合规样例和单项变异；纸张与边距不进入违规变异集。
- `wx_template.docx` 和本次人工确认的标准文档必须零误报；每个允许规则至少具有一个最小违规变异和一个边界容差样例。
- 覆盖“技术文档模板规则”、版本 `1.0.0`、来源版本和机器标识在 UI、报告与机器诊断中的分层展示。
- 覆盖旧规则包不再可选、运行时不自动回退、历史资产不进入交付白名单以及规则包完整性失败时 fail closed。
- 覆盖旧 `format_snapshot`、缓存和结果不能被 v2 静默读取，用户得到重新审查提示。
- 覆盖段落级、节级和文档级位置；页码可用、不可用、文档已编辑和重复文本场景不得产生伪锚点。
- 覆盖默认 UI、Markdown 和复制文本不出现规则键、英文枚举、原始浮点值或英文错误码；展开诊断仍能看到完整原始事实。
- D-0001 功能回归覆盖数字 `styleId=2/3/4`、标准标题 1–6、旧 `Heading1` 兼容、未知样式、缺失样式、受控 `basedOn` 继承和继承环路。
- `outlineLvl` 回归覆盖 0–5 的允许回退以及 6–8、9、负数、非数字和缺失值的非标题行为；OOXML 与 WPS COM 大纲值使用各自来源契约，不能共用裸整数解释。
- 使用仓库真实模板作为 D-0001 集成夹具，抽查代表性一级、二级、三级标题和正文不被升格，不只依赖人为构造的 `Heading1` styleId。
- 恶意 DOCX 回归覆盖 ZIP 条目超限、总解压超限、关键部件超限、CRC 损坏、加密成员、重复关键部件、相对或绝对危险路径、反斜线路径、畸形 XML、DTD、内部和外部实体。
- 覆盖大量关系和媒体资源仍受统一预算约束，验证和抽取期间不产生网络请求，也不向暂存根外写文件。
- 自动化通过只产生 `candidate`；Issue #59 的麒麟 V10、目标 WPS 和真实文档人工验收仍是 `target-accepted` 的必要条件。

## Out of Scope

- 不把纸张类型和四边页边距作为格式合规规则。
- 不把 `wx-doc-format` 的去除封面、生成题注、更新域、转换幂等或其它转换器成品合同作为输入文档审查标准。
- 不自动修改或写回 Word 文档格式。
- 不在本规格中增加多个可选规则包或自动猜测文档模板。
- 不把格式审查中文化扩展为 Word、Excel、PPT 全产品翻译工程。
- 不迁移旧裸数值格式快照、旧缓存或旧报告。
- 不承诺文档编辑后的物理页码保持不变。
- 不在 D-0001 中新增文档标题、附录标题等组织角色启发式。
