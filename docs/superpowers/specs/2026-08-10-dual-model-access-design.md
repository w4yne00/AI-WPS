# AI-WPS 模型平台与直接模型双接入设计

日期：2026-08-10

状态：访谈中

## 目标

在不破坏现有工作流平台链路的前提下，使 Word、Excel 和 PPT 的模型任务可以按配置选择工作流平台或模型直连。两种模型调用方式共用现有任务输入边界、提示词构造、结果预览、复制、写回限制、长任务协调、超时和 think 内容过滤要求。

## 已确认决策

### 1. 直接模型协议范围

- 首版模型直连只支持 OpenAI-compatible Chat Completions。
- 使用核心非流式文本协议，不支持厂商原生协议、工具调用或流式输出。
- 接入类型由配置明确选择，不根据 URL 自动猜测。
- 现有 `/chat-messages` 兼容接口继续作为工作流平台调用方式保留。

### 2. 按任务档案选择调用方式

- 每个模型配置独立保存模型调用方式、接口地址、认证信息和该方式所需的其他参数。
- 同一任务可以同时保存工作流平台配置和模型直连配置，并通过现有任务页下拉菜单切换。
- Word、Excel、PPT 以及同一宿主内的不同任务互不强制绑定调用方式。
- 任务提交时冻结所选模型配置，提交后的配置切换或修改不影响已排队、已运行的任务。

### 3. 用户界面统一命名

- 上位概念统一为“模型配置”，不再使用“工作流档案”。
- 配置中的协议选择字段称为“模型调用方式”。
- 两个选项分别称为“工作流平台”和“模型直连”。
- 设置页使用“模型配置 / 当前配置 / 新建模型配置 / 配置名称 / 配置备注”。
- 任务页下拉项同时显示自定义配置名称和模型调用方式。
- 用户界面、运行提示和新文档不直接使用具体平台产品名称；协议说明使用“工作流平台兼容接口”。

### 4. 服务地址与标准调用路径

- 普通设置只要求用户填写模型配置的服务地址，不单独显示或编辑调用路径。
- 工作流平台使用 `/chat-messages`，PPT 文档上传使用同一服务地址下的 `/files/upload`。
- 模型直连使用 `/chat/completions`。
- Adapter 根据模型调用方式组合最终调用地址，不根据用户输入的 URL 猜测调用方式。
- 高级诊断显示脱敏后的服务地址、标准调用路径和最终调用地址，便于排查重复 `/v1` 或路径错误。
- 首版不宣称兼容任意平台路径；`/workflows/run` 和厂商自定义路径不在已确认范围内。

### 5. 模型直连参数

- 普通配置要求填写服务地址、API Key 和模型名称。
- 折叠的高级参数只提供温度和最大输出 Token，两个字段均可留空。
- 高级参数留空时 Adapter 不发送对应字段，由模型服务使用默认行为。
- `stream` 固定为 `false`；首版不支持工具调用、厂商扩展参数、用户自定义消息角色或自定义请求 JSON。
- 请求超时继续由任务类型和长任务机制统一控制，不允许模型配置单独缩短既有等待预算。
- Adapter 继续负责构造任务提示词，模型配置不保存提示词正文。

### 6. 模型直连的 PPT 文档输入

- PPT 文档总结在模型直连下使用本地文档抽取，不调用厂商文件上传接口。
- Markdown 按 UTF-8 读取，保留标题、列表和段落边界。
- DOCX 使用目标机内的只读 ZIP/XML 解析，提取正文段落、标题和表格文本，不执行宏、不读取外部链接、不渲染嵌入对象。
- 抽取文本进入既有 PPT 文档总结提示词，并通过一次非流式 Chat Completions 请求处理。
- 原始文件仍使用现有暂存、单次消费、终态清理和进程退出清理规则；模型直连只改变执行阶段的数据准备方式。
- 工作流平台继续使用 `/files/upload` 和平台文件引用，不改变现有上传契约。
- 两种模型调用方式使用相同的页数选择、长任务状态、结果解析、预览、复制和 PPT 只读边界。

### 7. 模型直连文档超限策略

- 本地文档抽取后的文本只通过一次 Chat Completions 请求处理。
- Adapter 在发起网络请求前检查模型输入预算，超限时明确拒绝，不静默截断、不抽样、不自动拆分。
- 超限反馈披露抽取规模、允许预算和缩短文档建议，不声称已经总结文档。
- 超限任务不产生模型调用；任务拥有的暂存文件按失败终态立即清理。
- 当前已知直连模型为 GLM 5.2 和 DeepSeek v4 flash，两者现场上下文容量均为 40K。
- 现场直连服务地址形态为 `http://<内网地址>:<端口>/one-api/v1`，Adapter 应组合 `/chat/completions`；内网 HTTP 是受支持场景，不能强制 HTTPS。

### 8. 上下文容量配置

- 模型直连高级参数增加“上下文容量”，默认值为 `40000 Token`。
- 上下文容量只用于 Adapter 本地预算计算，不作为 Chat Completions 请求字段发送。
- 用户不展开高级参数时，GLM 5.2 和 DeepSeek v4 flash 均直接使用 40K 默认值。
- 后续模型容量变化时可以修改模型配置，不要求升级 Adapter 或维护模型名称容量表。
- 可用输入预算必须扣除 Adapter 构造的完整消息、最大输出 Token 和安全余量；本地 Token 估算采用保守算法，并明确不等同于厂商 tokenizer 的精确结果。
- 上下文容量、最大输出 Token、估算输入量和预算结论进入脱敏诊断，不记录用户正文。

### 9. 推理内容与最终结果

- 模型直连只从 `choices[0].message.content` 提取最终正文。
- `message.reasoning_content`、`reasoning` 和其他推理字段不进入任务结果、日志或前端。
- 最终正文字段中仍应用现有 `<think>...</think>` 清理规则，再交给八类任务各自的结果解析器。
- 只有推理内容而没有最终正文时返回“模型未返回最终结果”，不得把推理字段回退为答案。
- 工作流平台继续沿用既有 think 内容过滤，两种模型调用方式的用户可见边界一致。

### 10. 现有配置覆盖升级

- 首次加载新版本配置时执行幂等迁移，将现有工作流档案转换为工作流平台模型配置。
- 迁移保留配置 ID、任务归属、名称、备注、API Key 引用、创建/更新时间和当前激活状态。
- 迁移把升级前的统一 API URL 复制为每个现有模型配置的服务地址，不继续依赖全局地址继承。
- 现有 API Key 文件不移动、不改名、不重写，权限和安装保护规则不变。
- 旧全局 URL、`workflowProfiles`、`activeWorkflowProfiles` 和任务 Key 引用至少保留一个版本作为旧版回滚数据；新代码只以新模型配置结构为运行来源。
- 新建或修改的模型配置不反向同步旧字段，旧版本回滚只能继续使用升级前已经存在的平台配置，不能识别新建的模型直连配置。
- 重复启动、重复迁移和覆盖安装不得创建重复配置或改变当前选择。
- `adapter.json`、`run/provider_api_keys/`、写作规范数据库和备份继续受覆盖安装保护。

### 11. 配置完整度与真实调用状态

- 任务窗格右上角“已连接”继续只表示本地 Adapter 健康检查成功，不代表模型配置或模型服务可用。
- 模型配置列表只根据当前模型调用方式的必填字段显示“配置完整”或“配置不完整”。
- 保存模型配置只执行本地校验和持久化，不自动调用模型，不因慢模型阻塞设置页，也不产生意外费用。
- 配置编辑页提供次要操作“验证调用”；用户主动确认后才发起一次真实模型请求。
- 高级诊断分别记录最近调用成功、认证失败、服务不可达、超时、响应结构错误和未返回最终结果，不把本地字段完整包装成“模型已连接”。
- `/models` 不作为强制能力探测，因为并非所有 OpenAI-compatible 网关都实现该接口，且它不能证明 `/chat/completions` 和任务结果契约可用。

### 12. 下钻式任务契约验证

- “验证调用”位于单个模型配置编辑器的折叠“高级配置”内，不进入日常任务页、配置列表主操作区或设置首页。
- 验证调用使用当前配置对应任务的内置最小样例，不读取 WPS 当前选区，不发送用户文档或文件。
- 验证成功必须同时证明服务地址和认证可用、模型返回最终正文、当前任务结果解析器可以接受结果。
- 智能编写、智能仿写、文档审查、格式审查、Excel 智能分析、公式助手、PPT 智能总结和结构审查分别维护最小验证样例。
- 验证调用沿用对应任务的超时和 think 内容过滤，但不写回 Word、Excel 或 PPT，不创建正常任务历史，也不改变当前模型配置。
- PPT 智能总结的验证只覆盖内置当前页文本，不上传文件；PPT 文档上传、本地文档抽取和真实 WPS 对象读取必须通过实际任务或目标机验收验证。
- 启动验证前提示会产生一次真实模型请求和等待；验证状态只显示在高级配置与高级诊断中。

### 13. 移除全局模型接口编辑区

- Word、Excel、PPT 设置首页不再显示或编辑统一 API URL、全局模型接口或全局模型调用方式。
- 设置首页只显示当前宿主各任务的模型配置完整度摘要，并通过任务选项卡下钻管理配置。
- 每个模型配置自包含模型调用方式、服务地址、API Key 引用和该方式所需参数，运行时只读取任务当前激活的模型配置。
- 旧统一 URL 只作为迁移输入和旧版本回滚数据保留，不作为新版本运行时默认值、继承值或兜底值。
- 高级诊断按当前任务和当前配置显示有效服务地址、调用路径和最终调用地址，不再显示可能误导的“统一 API URL 已配置”。
- 模型接口就绪度改为只根据当前宿主各任务的激活模型配置计算。

### 14. 独立配置与安全复制

- 每个模型配置拥有独立 ID、API Key 引用和持久化 Key 文件，不建立全局共享凭据库。
- “新建模型配置”下钻入口提供“空白新建”和“从已有配置复制”，默认使用空白新建。
- 复制操作可以带入模型调用方式、服务地址、模型名称、配置备注和高级参数。
- API Key 只由 Adapter 在服务端从原 Key 文件复制到新的独立 Key 文件，不进入列表响应、浏览器状态或前端 JavaScript。
- 复制后的配置与来源配置没有运行时继承关系；任一配置的修改、换 Key、停用或删除不影响另一配置。
- 可复制来源限定为当前宿主已经存在的配置，保持 Word、Excel、PPT 的配置维护互不交叉。
- 配置复制不改变当前激活配置；用户保存后再明确选择是否激活。

### 15. 禁止跨配置自动降级

- 每次任务只使用提交时冻结的模型配置快照，不自动切换到同任务的其他配置。
- 工作流平台失败不自动改用模型直连，模型直连失败也不自动改用工作流平台。
- 失败反馈显示当前配置名称、模型调用方式、脱敏错误类别和“切换配置后重新提交”操作。
- 不对可能已经被服务端接受的 Chat Completions POST 自动重放，避免重复处理和重复费用。
- 工作流平台现有的输入节点兼容重试继续保留：只有首次 HTTP 400 明确拒绝后，才使用同一配置切换兼容载荷重试。
- 认证失败、超时、网络中断、限流、服务端错误、响应结构错误和最终正文缺失都不触发跨配置降级。

### 16. 结果来源披露

- 结果预览顶部显示一行低视觉权重的来源信息，取自任务提交时冻结的模型配置快照。
- 工作流平台显示配置名称和“工作流平台”；模型直连额外显示模型名称。
- 任务运行期间切换、修改或删除模型配置，不改变已有任务和结果记录的来源信息。
- 来源行不包含服务地址、端口、完整调用路径、API Key、Key 引用或认证来源。
- 来源行不进入结果正文、纯文本视图、复制内容、审查记录或任何 Word 写回内容。
- 详细调用阶段、耗时、最终调用地址和错误类别继续只放在高级诊断中。

### 17. 复用既有任务结果契约

- 模型直连首版不发送 `response_format`、JSON Schema 或厂商结构化输出扩展字段。
- 智能编写和智能仿写继续把清理后的最终正文交给现有文本结果流程。
- 文档审查、格式审查、Excel 智能分析、公式助手、PPT 智能总结和结构审查继续通过既有提示词要求 JSON 或 Markdown，并复用当前解析器。
- 既有代码块提取、字段校验、结构化解析失败和可复制原始正文降级行为保持一致。
- 工作流平台与模型直连不得因传输协议不同形成两套用户可见结果结构。
- 后续只有在目标网关和两个现场模型完成真实兼容验证后，才能另行考虑结构化输出扩展。

### 18. 八类任务系统提示词

- 模型直连使用两条消息：第一条 `system` 加载当前任务的内置任务系统提示词，第二条 `user` 使用 Adapter 现有完整任务提示词。
- 工作流平台继续只把现有完整任务提示词作为 query 发送，由平台内部配置同一版本的任务系统提示词，避免 Adapter 重复注入。
- 本版本重审并更新八类任务系统提示词：智能编写、智能仿写、文档审查、格式审查、Excel 智能分析、公式助手、PPT 智能总结和 PPT 结构审查。
- 八类任务分别保存为独立 Markdown 文件；智能仿写根据现有保护优先级、模板结构和只输出正文契约补齐首份独立模板。
- 模型配置不能编辑、覆盖或追加任务系统提示词；用户补充要求只进入当前任务的 user 消息。
- 任务系统提示词随版本发布并经过人工审阅，模型直连运行和任务级验证调用必须加载同一份文件。
- 工作流平台无法通过现有应用 API 自动读取或更新内部任务系统提示词，交付包必须提供相同 Markdown 文件供运维人员复制配置和核对版本。
- 任务系统提示词更新不修改模型配置、API Key、写作规范数据或用户文档。
- 八份 Markdown 是运行和运维的唯一内容来源，不另外维护可能漂移的“文档版”完整提示词。
- 单个模型配置的高级配置显示适用任务系统提示词的版本，并提供“查看/复制 System Prompt”。
- 操作文档引用对应 Markdown 文件及版本，不重复嵌入完整提示词正文。
- Adapter 不保存“平台已经同步”这类不可验证状态，也不把输出契约验证成功解释为平台内部提示词版本一致。

### 19. 统一错误与脱敏诊断

- 两种模型调用方式统一映射为中文错误类别：配置不完整、认证失败、地址或路径不可用、模型不可用、请求限流、处理超时、服务不可用、结果格式错误、最终正文缺失、输入超限、任务系统提示词缺失或损坏。
- 普通错误视图显示任务快照中的配置名称、模型调用方式、模型名称（仅模型直连）、中文说明以及修改配置或切换后重试操作。
- 高级诊断可以显示 HTTP 状态码、标准调用路径、脱敏最终调用地址、阶段耗时、内部错误代码和任务系统提示词版本。
- API Key、Authorization Header、用户正文、完整文档内容、公式正文、推理字段和原始错误响应正文不得进入任务响应、日志或诊断。
- 服务端原始英文错误只用于安全分类，不直接回显；无法安全分类时使用通用服务错误并保留脱敏状态码。
- 普通界面不得继续把认证、超时、模型不存在、限流或解析错误笼统称为“无法连接模型后台”。

### 20. 模型名称

- 模型直连的模型名称是必填自由文本，必须使用现场 OpenAI-compatible 网关接受的实际 `model` 标识。
- 界面可以展示 GLM 5.2 和 DeepSeek v4 flash 的示例，但不将产品展示名硬编码为请求值或固定下拉选项。
- 本地保存只校验非空、长度和禁止控制字符，不根据名称推断厂商、上下文容量、推理模式或参数支持情况。
- 不调用 `/models` 自动获取或暴露模型清单；模型标识的真实性通过用户主动执行的任务级验证调用确认。
- 任务提交快照和结果来源保留实际模型标识，高级诊断可以显示该标识但不得包含认证信息。

### 21. Bearer API Key 认证

- 工作流平台和模型直连首版统一使用 `Authorization: Bearer <API Key>` 和 JSON 内容类型。
- API Key 是模型配置必填项，继续保存在权限 `0600` 的独立 Key 文件中，不写入 `adapter.json`。
- API Key 不返回前端，不进入可序列化任务快照、日志、诊断、错误正文或结果来源信息。
- 不支持把 Key 放入 URL、查询参数或请求正文，不支持自定义认证 Header、Basic Auth、AK/SK 签名或无认证模式。
- 从已有配置复制时由 Adapter 服务端复制 Key 文件，前端仍无法读取明文。

### 22. 智能编写与智能仿写迁移为后台模型任务

- 智能编写和智能仿写不再依赖同步 POST 持续等待模型返回，正式前端改用提交、查询和排队取消协议。
- 两项任务使用 `clientJobId` 幂等；提交超时、短暂断连和重开任务窗格不得重复调用模型。
- 提交时冻结用户输入、任务选项、写作规范结果、模型配置、认证、模型参数和任务系统提示词版本。
- 公共状态和阶段复用 queued、running、completed、failed、cancelled，以及准备、模型处理和结果解析阶段；不显示估算百分比。
- 只有 queued 状态允许取消；运行中的阻塞模型请求不伪装成可取消。
- 智能编写的原文、对照高亮、预览、复制和既有写回行为保持不变；智能仿写继续只有预览、纯文本和复制，不新增对照或写回。
- 旧同步接口保留一个版本作为兼容包装并通过同一后台执行器等待结果，三宿主正式前端不再调用旧同步接口。
- Adapter 重启后，前端保存但服务端不存在的任务显示明确中断提示，不自动重新提交。

### 23. 共享容量内的交互任务优先

- 智能编写和智能仿写标记为交互模型任务；其余已接入协调器的任务为常规长任务。
- 三宿主继续共享全局同时运行 `2`、排队容量 `8` 的边界，不创建独立线程池或额外绕过容量的连接。
- 已运行任务不被抢占；执行槽释放时，排队中的交互模型任务优先于常规长任务。
- 交互任务内部和常规任务内部各自保持 FIFO。
- 连续调度 3 个交互任务后，如存在常规任务，必须调度等待最久的常规任务，避免饥饿。
- `queuePosition` 按协调器当前真实调度顺序计算，不能只显示提交顺序。
- 排队取消、终态保留、认证释放、重启中断和脱敏诊断继续使用同一协调器规则。

### 24. 交互模型任务等待预算

- 智能编写和智能仿写的 Provider 执行上限统一为 `600 秒`。
- 600 秒从任务获得执行槽并开始模型请求时计算，排队时间不占用 Provider 执行预算。
- 前端后台任务恢复和轮询总窗口继续使用既有长任务级等待边界，不依赖一次 HTTP 连接。
- 超过 600 秒后任务进入 failed，用户反馈明确为“模型处理超过 10 分钟”，不得显示成 Adapter 无法连接。
- 任务超时后不自动重放、不切换模型配置；模型服务是否仍在处理按现有阻塞 API 限制如实说明。
- 文档审查、Excel 智能分析、公式助手、PPT 智能总结和结构审查继续使用各自现有长任务 Provider 预算，不统一缩短为 600 秒。

### 25. 任务系统提示词完整性

- 八份任务系统提示词是只读发布资产，不作为目标机用户可编辑配置。
- manifest 为每项任务记录任务类型、提示词版本、Markdown 文件名和 SHA256 摘要。
- Adapter 启动或首次加载时校验任务映射、文件存在性和摘要；缺失、未知任务或摘要不一致时，相关模型直连任务明确失败。
- 工作流平台任务不依赖本地提示词加载，因此本地文件损坏不应伪装成平台连接失败，也不应阻断平台任务。
- 覆盖升级可以更新发布提示词和 manifest，但不得修改模型配置、API Key、写作规范数据或用户文件。
- 组织术语、文体、保护项和去模板化定制继续通过写作规范库维护，不直接修改任务系统提示词。
- 诊断只记录任务提示词版本、文件状态和摘要前缀，不记录完整提示词正文。

### 26. 服务地址规范化

- 服务地址允许内网 `http://` 和 `https://`，保存时删除首尾空白和末尾斜杠。
- 如用户粘贴的地址以 `/chat-messages`、`/files/upload` 或 `/chat/completions` 结尾，保存时移除已知标准后缀并提示已经规范化。
- 后缀识别只用于得到服务根地址，不得据此推断或改变用户明确选择的模型调用方式。
- 主机、端口以及 `/one-api/v1` 等自定义根路径保持不变。
- URL 中包含用户名、密码、查询参数或 fragment 时拒绝保存，避免认证信息和非标准路由混入服务地址。
- 保存预览和高级诊断显示由规范化服务地址与当前标准路径组成的最终调用地址；普通任务页不显示地址。

### 27. 模型配置 API 与旧接口兼容

- 新运行时使用 `/provider/model-configurations` 资源及创建、修改、换 Key、激活、复制、验证和删除操作。
- 三宿主新前端只调用模型配置 API，不继续使用“工作流档案”命名的接口。
- 旧 `/provider/workflow-profiles` 接口保留一个版本作为兼容包装，只能读取和操作迁移后的工作流平台配置，不能返回或修改模型直连配置。
- 旧接口兼容期结束后在下一主功能版本移除，不形成永久双写。
- 模型配置响应包含配置 ID、任务归属、名称、备注、模型调用方式、服务地址、模型名称、非敏感高级参数、Key 是否已配置和提示词版本，不包含 Key 明文。
- FastAPI 与 standalone 对模型配置校验、状态码、错误代码、复制、验证和删除行为保持等价。
- 激活配置与任务提交并发时，任务只认提交快照；配置操作不得修改已经排队或运行的任务。

### 28. 正式运行禁止静默 mock

- 正式运行中，当前任务没有激活的完整模型配置时返回配置错误，不生成模拟正文或模拟分析结果。
- 模型认证、网络、超时、限流、解析或最终正文缺失时返回对应真实错误，不回退 mock。
- 只有测试或开发环境显式设置 `AI_WPS_ENABLE_MOCK_PROVIDER=1` 时才允许 mock。
- mock 结果来源必须显示“开发模拟”，不得显示为工作流平台、模型直连或真实模型名称。
- 格式审查的本地确定性检查、写作规范检查、公式本地检查和 PPT 本地结构检查属于正式本地能力，不按 mock 处理，既有降级边界保持不变。
- 自动化测试必须显式注入 mock 开关或 fake provider，不能依赖生产默认行为。

### 29. 40K 模型输入预算

- 上下文容量默认 `40000 Token`；最大输出 Token 留空时，本地预算按 `8000 Token` 输出保留计算，但不向模型发送 `max_tokens`。
- 安全余量为上下文容量的 `10%`，40K 默认即 `4000 Token`。
- 40K 默认可用输入预算约为 `28000 Token`，完整 `system + user` 消息必须共同落在该预算内。
- 用户显式填写最大输出 Token 时，本地预算使用该值，并在 Chat Completions 请求中发送对应字段。
- Adapter 对全部模型直连任务执行保守 Token 估算；估算结果只用于拒绝超限请求，不自动裁剪、压缩或拆分内容。
- 上下文容量、输出保留、安全余量、估算输入和是否超限进入脱敏诊断，不记录实际消息正文。

### 30. 平台无关的任务系统提示词

- 八份任务系统提示词全部改写为平台无关内容，只使用“用户消息”“输入内容”“任务模式”等中性术语。
- 提示词正文不出现具体平台产品名称、`sys.query`、`userinput.query`、`userinput.files`、工作流节点名称或文档提取节点变量。
- PPT 智能总结根据 user 消息中明确提供的 `sourceMode` 区分当前页和文档模式，不根据平台文件变量推断。
- 模型直连把本地文档抽取结果放入 user 消息；工作流平台由应用编排把平台输入整理成同一语义的 user 消息。
- 角色、事实边界、写作规范优先级、输出契约、只读/写回限制和禁止展示推理内容的要求在两种调用方式间保持一致。
- 同一 Markdown 不做按 Provider 的运行时字符串替换，不维护平台版与直连版分支。

### 32. 克制型 Apple 界面原则

- Word、Excel、PPT 的设置页和任务页沿用同一交互骨架，分别保留 Word 蓝、Excel 绿、PPT 橙作为宿主强调色，不改变既有品牌辨识。
- 界面采用系统字体、清晰信息层级、稳定空间关系和紧凑下钻结构；任务窗格首层只显示当前任务必需信息和已有功能选项卡。
- 模型配置的常用字段处于主编辑层，高级参数、验证调用、最终地址和诊断信息放入可展开的高级配置层。
- 操作必须在按下、保存、验证、排队和完成时提供即时且可撤销语义明确的反馈；不得用无意义刷新按钮替代状态同步。
- 动效仅用于说明层级和状态变化，保持短促、可打断，并支持 `prefers-reduced-motion`；不引入大面积毛玻璃、夸张弹簧、拖拽手势或装饰性动画。
- 窄任务窗格避免嵌套卡片、横向挤压和长表单一次性展开；错误贴近对应字段，敏感信息不因动画、预览或诊断而暴露。
- 本轮只统一界面语言和模型配置交互，不改变八类任务结果、复制、预览、审查记录和写回边界。

### 33. 模型配置同页下钻导航

- 设置界面采用同页下钻层级：设置首页、任务选项卡与配置列表、配置编辑、高级配置。
- 不使用模态弹窗承载完整配置表单，也不在配置列表内展开长表单，避免窄任务窗格出现上下文遮挡和滚动层级混乱。
- 下钻页左上角提供明确返回操作，并保留上一级选中的任务选项卡、列表滚动位置和当前配置位置。
- 常用配置字段留在配置编辑主层；低频模型参数、验证调用、最终调用地址、提示词版本和诊断信息继续放在高级配置层。
- 层级切换使用约 `180-220ms` 的轻量位移与透明度过渡，动画必须可打断；启用减少动态效果时改为无位移的即时切换或短淡入。
- 页面切换不触发配置保存、模型验证或网络调用，所有有副作用的操作均由用户明确提交。

### 34. 未保存配置保护

- 配置字段发生变化后，在导航栏以低干扰方式显示“未保存”，不对每次输入弹出提示。
- 用户返回上一级、切换任务选项卡或关闭设置且操作会丢失修改时，提供“继续编辑”和“放弃修改”确认。
- 保存成功后立即清除未保存状态，并在当前页面显示短暂、非阻塞的成功反馈。
- 字段校验失败或服务端保存失败时停留在编辑页，保留当前输入，并把错误显示在对应字段附近。
- API Key 和其他配置草稿不得写入 `localStorage`、查询字符串、日志或可恢复的前端持久化介质。
- 对无法拦截的 WPS 进程退出或任务窗格强制销毁，不承诺恢复未保存草稿；已经成功保存的配置以 Adapter 数据为准。

### 35. 模型调用方式切换

- 编辑已有配置时允许在“工作流平台”和“模型直连”之间切换，但切换属于破坏性表单操作，必须先显示影响确认。
- 用户确认后保留配置名称、配置备注等通用字段，清空原调用方式的专属字段和不兼容高级参数。
- API Key 不跨调用方式自动沿用，切换后必须由用户重新录入或通过服务端“复制已有配置”流程重新复制。
- 用户取消确认时，调用方式和全部当前输入保持不变。
- 前端隐藏字段不得继续随保存请求提交；服务端也必须按目标调用方式使用白名单重建配置，不能保留无效旧字段。
- 切换完成仍属于未保存草稿，只有用户明确保存后才更新 Adapter 中的正式配置和后续任务快照。

### 36. 激活配置删除保护

- 非激活配置可以在二次确认后删除；确认内容显示配置名称、所属任务和删除后果，不显示 API Key 或服务地址细节。
- 当前任务正在使用的激活配置不能直接删除，界面优先要求用户先激活同一任务下的另一项配置。
- 同一任务没有其他配置时，用户可以明确选择“停用并删除”；确认页必须说明该任务将变为“未配置”且无法提交模型任务。
- 系统不得在删除后自动激活列表第一项，也不得跨宿主或跨任务选择替代配置。
- 删除只影响后续任务；已经排队或运行的任务继续使用提交时冻结的配置快照和临时认证句柄。
- 删除完成后返回对应任务配置列表，并即时更新任务页配置状态，不依赖手动刷新。

### 37. API Key 独立维护

- 编辑已有配置时不回填 API Key 明文、掩码值或可复制占位符，只显示“已配置”或“未配置”状态。
- API Key 使用独立“配置/更换”操作进入紧凑输入层，与名称、备注、地址和模型参数的普通保存操作分离。
- 新 Key 需要输入两次并在前端做一致性校验；两次输入均使用密码输入控件，并允许用户按需短暂显示当前输入。
- 前端不得读取旧 Key，也不得通过“留空代表不修改”等隐式规则把空值提交为新 Key。
- 更换 Key 由服务端原子写入新的权限 `0600` 文件；写入失败时保留原 Key，成功后再清理旧文件。
- 更换成功后立即清空前端输入和内存引用，只更新 Key 配置状态，不自动执行验证调用。

### 38. 紧凑模型配置列表

- 每个任务选项卡使用紧凑行式列表展示模型配置，不使用占用纵向空间的大卡片。
- 主行显示配置名称、模型调用方式、配置完整状态和激活标记；模型名称或配置备注仅在实际有值时显示为第二行。
- 未填写备注时不显示“暂无备注”等占位文本；工作流平台配置没有模型名称时也不保留空白位置。
- 点击整行进入同页配置编辑层；复制、激活和删除收纳在行尾更多菜单中，菜单项按当前状态动态启用。
- 激活配置使用文字与图形状态共同表达，不能只依赖宿主强调色；不完整配置允许编辑和复制，但不能激活或验证。
- 列表为空时只显示简短空状态和“新建模型配置”主操作；列表增长后保持固定行高规则和纵向滚动，为 Excel、PPT 后续新增任务选项卡预留一致扩展方式。

### 39. 验证调用内联反馈

- “验证调用”保留在配置编辑页的高级配置层，不跳转到独立结果页，也不使用只出现数秒的瞬时通知承载结论。
- 验证期间按钮显示运行状态并防止重复提交；用户离开当前层级时应明确提示验证仍在进行，但不得锁死整个设置页。
- 验证完成后在按钮下方显示紧凑摘要，包括成功或失败、总耗时和完成时间；失败摘要使用统一中文错误分类和下一步操作。
- HTTP 状态、标准路径、脱敏最终地址、分阶段耗时、内部错误码和提示词版本放入默认折叠的详细诊断。
- 验证结果不自动激活配置、不自动保存未保存字段、不关闭编辑页，也不改变任务页最近一次正式任务诊断。
- 页面会话结束后无需把完整验证响应持久化；服务端日志只保留既定脱敏诊断字段，不保留合成输入和模型正文。

### 40. 任务页模型配置选择器

- Word、Excel、PPT 任务页的模型配置下拉菜单只显示当前宿主、当前任务且配置完整的模型配置。
- 不完整、已删除、其他任务或其他宿主的配置不出现在任务选择列表中，也不能通过前端缓存继续提交。
- 每项显示配置名称和模型调用方式；模型直连项补充模型标识，工作流平台项不显示空模型占位。
- 当前激活项使用勾选标记和文字共同表达，不能只依赖颜色。
- 下拉菜单底部提供“管理模型配置”，直接进入设置页对应任务选项卡，并保留从任务页返回的路径。
- 当前任务没有可用配置时，选择器显示“未配置”，主任务按钮禁用并提供直达配置入口，不生成模拟结果。

### 41. 任务默认配置持久化

- 用户在任务页选择另一项模型配置后，Adapter 立即把该配置保存为当前宿主、当前任务的默认激活配置。
- 切换请求完成前，选择器显示轻量进行中状态并暂时禁止提交新任务，避免界面选择与服务端快照不一致。
- 保存成功后更新勾选项和任务页来源信息；保存失败时恢复原选择，并显示可操作的中文错误。
- 已经排队或运行的任务继续使用提交时冻结的配置快照，不随默认配置变化而切换地址、Key、模型或参数。
- 重新打开任务窗格、重启 WPS 或重启 Adapter 后，选择器从服务端恢复该任务最近成功保存的默认配置。
- 不提供“仅本次使用”的隐式临时模式；用户的下拉选择具有明确、可预测的后续默认含义。

### 42. 保存后验证

- 验证调用只允许针对已经保存、配置完整的模型配置执行，不直接测试尚未持久化的表单草稿。
- 配置编辑页存在未保存修改时，“验证调用”不可用，并在控件附近提示“请先保存配置”。
- 保存配置本身不触发模型调用；保存成功后由用户再次明确点击“验证调用”。
- 验证请求按已保存配置 ID 和版本读取服务地址、认证、调用方式、模型参数和任务提示词，不能接受前端附带的临时连接字段。
- 配置在验证排队或运行期间再次被修改时，本次验证继续使用提交快照，并在结果中提示“配置已在验证后发生变化”。

### 43. 最近验证摘要

- Adapter 为每项模型配置保存最近一次验证的脱敏摘要，包括成功或失败、完成时间、总耗时、配置版本和任务系统提示词版本。
- 最近验证摘要只在配置编辑页的高级配置层展示，不进入配置列表主行、任务页顶部连接状态或结果正文。
- 配置的服务地址、调用方式、API Key、模型标识、模型参数或任务提示词版本发生变化后，原摘要标记为“结果已过期”。
- “验证成功”只描述该配置版本在对应时间完成了一次任务级探测，不承诺模型服务持续在线，也不替代任务提交时的真实错误处理。
- 不保存验证使用的合成用户消息、模型返回正文、推理内容、完整 URL、认证信息或原始错误响应。
- 最近验证摘要遵循现有运行数据保留与脱敏规则；删除模型配置时一并删除其验证摘要。

### 44. Adapter 连接状态自动同步

- 任务窗格右上角连接状态只表示前端与本地 Adapter 的健康检查结果，文案使用“已连接”“连接中”“未连接”，不显示笼统的 `OK`。
- 打开任务窗格、页面从后台恢复可见、从设置返回任务页或从任务页进入设置时立即执行健康检查。
- 窗格可见期间进行低频健康轮询；成功时使用稳定间隔，失败时采用有上限的指数退避，恢复后回到正常间隔。
- 保存、复制、删除、激活模型配置成功后，相关配置完整度和选择器状态由操作响应直接更新，不再额外依赖刷新请求。
- 删除没有明确业务作用的手动刷新按钮；重试入口只在真实连接失败状态中作为上下文操作出现。
- 健康检查不得调用模型服务、验证 API Key 或改变模型配置，不能把模型后台慢响应误判为 Adapter 未连接。
- 三宿主共享相同状态机和轮询策略，仅使用各自宿主强调色呈现非语义性视觉细节。

### 45. Adapter 断开时的只读快照

- Adapter 暂时断开时保留前端最近一次成功加载的任务与模型配置内容，并统一标记为“上次同步”及对应时间。
- 只读快照不得继续显示为实时有效状态；右上角状态切换为“未连接”，配置完整度和验证摘要保留但增加离线语义。
- 保存、复制、删除、激活、验证调用和模型任务提交全部禁用，避免把离线操作伪装为已经成功。
- 前端不建立离线修改队列，不在恢复连接后自动提交用户离线期间的输入或配置变化。
- 健康检查恢复后重新从 Adapter 拉取当前宿主的配置、默认激活项和必要状态，再解除只读限制。
- 如果服务端数据与只读快照不同，以 Adapter 当前数据为准，并通过克制的内容更新提示说明已重新同步。

### 46. 设置下钻保留任务状态

- 设置页是当前任务窗格内的同页下钻层，不是会重新初始化应用的独立入口。
- 从任务页进入设置时保留当前输入、WPS 选区快照、任务选项、模型配置选择、后台任务编号、排队或运行状态以及结果预览。
- 返回任务页后只同步配置列表、默认激活配置和 Adapter 健康状态，不清空内容、不自动重新读取选区、不重新提交模型任务。
- 设置期间完成的模型配置切换只影响返回后提交的新任务；已排队、运行或完成的任务仍绑定原提交快照。
- 若设置期间 Adapter 断开，返回任务页继续显示原状态的只读快照，并按统一重连规则恢复。
- 三宿主使用相同的页面状态保存边界；Word 的写回状态、Excel 的区域快照和 PPT 的页面/文档来源状态分别按既有逻辑保留。

### 47. 分步建立不完整配置

- 新建模型配置只要求先确定所属宿主、所属任务、配置名称和模型调用方式，即可在 Adapter 中保存为不完整配置。
- 工作流平台缺少服务地址或 API Key，模型直连缺少服务地址、API Key 或模型标识时，配置明确标记为“配置不完整”。
- 不完整配置可以继续编辑、补充 Key、修改名称备注或删除，也可以作为同宿主复制操作的来源，但不能激活、验证或提交模型任务。
- 高级可选参数缺失不影响完整度；字段填写无效与字段缺失分别显示具体错误，不能都归为“未配置”。
- 创建不完整配置后关闭任务窗格不会丢失；再次进入对应任务选项卡时从 Adapter 恢复。
- 配置完整度由 Adapter 按调用方式统一计算，前端只展示服务端结果，避免 Word、Excel、PPT 各自形成不同判断。

### 48. 配置名称唯一性

- 配置名称只要求在同一宿主、同一任务范围内唯一，不要求跨 Word、Excel、PPT 或跨任务全局唯一。
- 保存前去除名称首尾空白，并按大小写不敏感的规范化值检查冲突；名称正文中的合理空格和中文保持原样。
- 配置列表、任务页选择器、结果来源和错误反馈均使用保存后的显示名称，内部关联始终使用不可变配置 ID。
- 复制已有配置时默认在原名称后追加“副本”；发生冲突时追加递增序号，用户保存前仍可修改。
- 服务端负责最终唯一性校验，前端即时校验只用于改善输入反馈，不能替代并发写入保护。

## 新发现的当前代码事实

- `POST /word/smart-write` 和 `POST /word/smart-imitation` 当前同步执行 Provider 请求，没有任务编号、状态查询或恢复接口。
- 两项 Provider 调用没有任务专用超时，实际回退到当前全局默认等待预算。
- Word 前端对两项任务直接等待一次 fetch 结果；单纯延长 Provider 超时仍会保留长连接断开和重复提交风险。

## 当前代码事实

- Adapter 当前由 `ProviderClient.post_task` 统一发送工作流平台兼容的 `/chat-messages` 请求，固定使用 `query`、`inputs`、`response_mode`、`user` 和 `files` 结构。
- 工作流平台新旧用户输入节点兼容通过首次 HTTP 400 后切换 `inputs.query` 与顶层 `query` 的方式完成。
- 现有工作流档案只保存任务、名称、备注和 API Key 引用；统一 API URL、`/chat-messages` 路径和提供方类型仍是全局配置。
- 八类模型任务共用 Adapter 内的提示词构造和任务结果解析，直接模型接入可以复用这些能力。
- PPT 文档总结当前依赖工作流平台 `/files/upload` 和平台文件引用，不能直接套用 Chat Completions 文本请求。
