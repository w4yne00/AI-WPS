# 在 v0.25.1-alpha 收敛格式审查后以一次性安装断代进入 Preview

现有 `v0.25.0-alpha` 候选仍沿用 `Phase1` 包名、安装目录、脚本入口和版本规则，但产品已经覆盖 Word、Excel、PPT 三宿主及多类独立任务，`Phase1` 不再能准确表达产品阶段。同时，格式审查在目标 WPS 中仍存在正文大纲级别被误判为标题、模型调用状态不可见等阻断缺陷，因此当前候选不满足预览版本的现场可用性要求。

决定先发布 `v0.25.1-alpha` 修复候选，只收敛格式审查正确性、模型调用诊断和目标机验收，不在该版本中引入素材编排或安装体系断代。该候选完成麒麟、WPS 和模型直连现场验收后，后续功能线以 `v0.26.0-preview.1` 正式进入 Preview。

`v0.26.0-preview.1` 同时建立中性的产品包名、安装根目录、安装脚本和发布标识，不再使用 `Phase1` 作为当前产品身份。此次转换是一次性安装基线断代：不自动搬迁旧安装根、配置、API Key、运行数据或目录文件，也不承诺旧入口兼容；旧目录不由安装器自动删除，用户按迁移说明重新安装并配置。该取舍避免把历史安装地址空间和兼容包装长期带入新的预览基线，代价是现有用户需要完成一次人工重新配置。

从 `v0.26.0-preview.1` 起，发布通道与交付验证状态分开表达：`alpha`、`preview` 描述产品成熟度；`candidate`、`target-accepted` 或 `rejected` 描述某一构建是否通过自动化及目标机验收。进入 Preview 不等于构建已经完成目标机验收。

`v0.26.0-preview.1` 成为后续升级基线。此后版本必须提供保留配置和运行数据的兼容升级或以该基线为前提的增量升级包，不再把全新全量安装作为常规升级方式。需要再次打破升级兼容时，必须形成新的明确架构决策和迁移方案，不能由包名或目录调整隐式触发。
