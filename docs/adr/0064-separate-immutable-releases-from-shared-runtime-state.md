# 不可变发布目录与共享运行状态分离

当前 Adapter 程序、依赖、配置、Key、SQLite、日志和 PID 混放在 `adapter-start-kit`，升级必须先搬出运行数据、覆盖整个目录再放回，容易遗漏、覆盖并阻碍版本级回退。决定从 `v0.23.1-alpha` 起将安装根目录拆分为 `releases/<version>`、当前发布代际指针 `current`、正式运行数据 `state`、一致性快照 `backups` 和临时运行区域 `var/{logs,run,transactions}`。程序、脚本、发布私有依赖和清单进入安装后不可由运行时修改的版本目录；配置、API Key、任务映射和写作规范数据库只写入 `state`，并通过明确路径传给 Adapter；日志、PID 和事务记录不进入运行数据快照。从旧布局迁移必须使用写时复制，发布清单声明数据结构版本，程序回退使用与该代际匹配的已校验快照，不再把数据复制回程序目录。该变更需要重写安装和启动路径，但消除了程序覆盖与状态保存的结构性冲突。
