# 从明确白名单重新组装交付包

历次版本在既有交付目录上持续追加和复制，容易携带旧版本归档、开发脚本、测试、缓存、兼容入口及目标环境不需要的依赖。决定从 `v0.23.1-alpha` 起重新组织交付包，使用明确白名单从安装器、Word/Excel/PPT 插件、Adapter、麒麟 Python 3.8 目标 Wheel、发布清单、诊断/验收/恢复脚本、必要文档和许可证重新组装，不再复制旧包后逐项删除。交付产物明确排除旧版本包和重复归档、测试与开发脚本、缓存临时文件、现场日志/PID/配置/API Key/数据库/备份、被正式入口替代的 standalone 或兼容启动残留、非目标架构或运行时依赖，以及未被清单引用的文档和样例；构建后执行白名单、文件哈希、依赖引用闭包和敏感信息审计。清理仅作用于生成的交付产物，不直接删除源码仓库中的历史设计、测试和追溯材料，仓库历史删除需要另行评审。该方案需要维护构建清单，却能从源头阻止历史残留进入目标机，并保持审计和追溯证据。
