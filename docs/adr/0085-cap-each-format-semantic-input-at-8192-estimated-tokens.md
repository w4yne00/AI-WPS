# 将单次格式语义输入限制为 8192 个估算 Token

决定首版每次格式语义调用最多携带 `8192` 个估算输入 Token，并以版本化的保守中英文混合估算方法动态组批，不引入厂商专用 tokenizer。工作流平台直接采用该任务上限，为 Adapter 无法读取的自定义系统提示词和工作流节点预留空间；模型直连的实际输入上限取 `8192` 与“配置上下文容量减去当前 System Prompt、有效输出预算和百分之十安全余量”的较小值。输入仅包含候选所需文本片段、结构关系和规范化格式事实，不发送整篇文档；单个完整候选仍超限时不得静默截断或拆成失去共同上下文的独立判断，必需候选标记无法判定并使覆盖状态为部分，可选候选仅使语义增强降级。该保守上限降低大上下文模型的单批吞吐率，但隔离了 Dify 内部提示词不可见、不同分词器偏差和异常文档造成的上下文溢出风险。
