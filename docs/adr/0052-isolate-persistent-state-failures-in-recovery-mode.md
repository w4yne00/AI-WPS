# 持久化子系统失败时进入恢复模式

候选构建的代码、完整性和基础 API 契约已经通过事务式升级验证后，持久化数据仍可能在首次读取或迁移时失败。决定此类故障不再使 Adapter 整体退出：模型配置、任务路由等核心数据失败时进入恢复模式，进程、健康检查、脱敏诊断、备份和显式恢复接口保持可达，但业务未就绪；仅写作规范等非核心增强数据失败时进入降级状态，核心 Word 任务按既有规范降级契约继续执行，故障子系统的管理操作禁用。两种状态都必须保持原始故障数据只读，不得以空配置启动、静默重置、覆盖或删除。核心代码无法导入、候选包损坏或基础 API 契约不兼容仍属于候选验证失败，应保留旧版本，不得用降级或恢复模式掩盖发布缺陷。该策略增加了状态契约和前端处理复杂度，但避免非核心增强故障造成整体停机，同时为核心数据异常保留可操作恢复入口。
