# 在 v0.24.0 验收完成后才启动 v0.25.0 格式审查代码开发

当前开发主线已经进入 `v0.24.0` Word 全篇文档审查，Issue #35 至 #40 已关闭，白名单交付包和目标机验收仍分别由 Issue #41、#42 追踪。此前把确定性格式审查同时安排进 `v0.24.0` 会混淆当前版本的完成条件，并允许未来功能在文档审查尚未完成正式目标机验收时改变同一交付基线。

决定将 Word 全篇文档审查固定为 `v0.24.0` 功能线；该功能发现的缺陷使用 `0.24.x` 补丁位迭代，不把格式审查或相关体验改造混入补丁版本。确定性优先格式审查、受限模型语义、默认关闭的图片语义能力、Word 设置页对齐、三宿主任务选择器标签精简以及 Excel/PPT Ribbon 图标替换统一安排到 `v0.25.0`。只有 GitHub Issue #42 处于 `CLOSED` 状态后，才允许开始任何实现 `v0.25.0` 行为的生产代码、测试代码、协议、资源、清单或打包修改；在此之前只允许规格、ADR、tickets 和只读调研。Issue #42 若在开发期间重新打开，立即暂停新的 `v0.25.0` 实现和集成交付，待其再次关闭后继续。

该门禁使 `v0.24.0` 的目标机验收成为 `v0.25.0` 的可验证基线，并让文档审查缺陷能够通过独立的 `0.24.x` 补丁快速修复。代价是格式审查代码不能与剩余的文档审查交付工作并行，但可避免在尚未验收的抽取、任务协调、生命周期和交付包基础上叠加第二套大型审查状态机。
