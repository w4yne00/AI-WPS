# 三宿主共享直连服务配置，任务独立选择模型

AI-WPS 不再把两种模型调用方式都封装为按任务隔离的完整配置。工作流平台继续由每个功能独立维护配置；模型直连则在同一本地 Adapter 运行环境中只保存一份服务地址和 API Key，并允许 Word、Excel、PPT 全部功能共享选择该直连服务。每个功能仍独立保存模型标识及温度、Token、图片能力等任务参数，任务提交时冻结服务、认证指纹和任务选择快照。该决定取代 ADR-0019；它减少重复录入并维持任务能力差异，代价是需要迁移既有重复直连配置，并保证共享服务的修改、删除和密钥轮换不会静默改变已排队或运行任务。

同一运行环境最多保存五份共享直连服务配置。每份服务保存一个默认模型，尚未单独设置的功能继承该默认值，之后可以按功能覆盖。模型列表只辅助选择：设置页提供手动刷新按钮，并显示最近一次成功获取时间；保存或更换地址、Key 时可以尝试刷新，但刷新失败不导致保存失败，发起任务也不要求目录获取成功。列表过期、目录不可访问、刷新失败、目录为空或新列表不含已保存模型时，不清空已保存的默认模型或功能级选择，也不阻断任务。任务按已保存的服务、凭据、模型 ID 和参数发起真实调用，由服务返回成功或真实错误，不静默切换模型或服务。无论模型目录是否可用，服务默认模型和各任务模型选择下拉框中均常驻手填模型管理入口（「输入 / 管理手填模型...」），并支持维护每个服务的手填模型列表（`customModels`）。用户可自由即时添加多个手填模型或单项删除，无需强依赖测试调用即可直接保存和执行任务；删除正在使用的手填模型时执行平滑重置，受影响的服务默认模型置空，任务选择平滑回退为继承服务默认状态，不阻断删除。

三宿主设置首页都提供同一个“直连服务”入口；各功能页只维护任务独占的工作流配置和任务模型选择。被任务引用的共享服务不得直接删除，界面必须列出引用功能并要求先改绑；修改服务地址前也必须披露受影响功能。升级合并后若不同任务保留不同模型，不猜测默认模型，现有任务继续使用原绑定，新功能首次使用前由管理员补选服务默认模型。

PPT 模板正文页与整套生成共用“资料大纲”（`ppt.material_outline`）的当前模型设置，不另设模型入口。每次模板页提交时显式解析并冻结资料大纲的服务、凭据、模型和参数；执行任务类型、提示词与结果格式仍为 `ppt.template_page`。此前通过 API 单独保存的模板页模型绑定不再参与生成，已有记录不删除；资料大纲未配置或调用失败时明确报错，不回退至旧模板页配置或其他服务。本次调整不扩展模板页既有的文字资料输入范围。

任务模型选择的 `maxOutputTokens` 范围为 1–16384，`contextWindowTokens` 范围为 1000–2000000；两者同时显式设置时，`contextWindowTokens - maxOutputTokens - max(floor(contextWindowTokens × 10%), 1)` 必须大于 0。保存校验、全篇审查就绪判定和实际请求预算必须使用同一公式。

Word 智能编写（`word.smart_write`）与智能仿写（`word.smart_imitation`）任务设置移除独立“验证调用”按钮，在用户点击“保存并设为当前”时执行双轨验证流：对目录模型（含继承目录服务默认值），前置自动验证流式能力并做真实网络探测，验证成功后原子激活，失败则阻断保存、回显错误并保留草稿与当前有效选择；对手填模型（含继承手填默认值），本地校验通过后立即原子激活并保存，随后在后台异步发起非阻塞流式能力探测，探测失败只更新能力记录为不支持，绝不撤销激活或静默回退选择；未取得流式验证前模型安全回退为普通阻塞调用执行任务。有效流式能力记录（`validated` / `unsupported`）基于服务修订、服务地址、API Key 指纹和精确模型名复用，并发探测请求自动去重。Word 审查类任务（`word.format_review`、`word.document_review`）以及 Excel、PPT 宿主保留独立“验证调用”机制，不扩展流式预览。

Ribbon 入口及任务页模型菜单切换已保存的直连服务时，仅向本地 Adapter 保存当前选择并读取配置，不触发目录模型的前置验证，也不启动手填模型的后台探测。切换复用服务与模型已有的有效能力记录，不受远端模型响应延迟影响；未验证或不支持流式的模型仍按既有规则使用普通调用。上述双轨验证仅用于设置页的“保存并设为当前”，切换仍保留本地配置完整性检查、保存超时提示和任务隔离。
