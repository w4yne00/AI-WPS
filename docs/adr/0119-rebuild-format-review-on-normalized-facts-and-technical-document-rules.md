# 以规范化格式事实和技术文档模板规则重建格式审查基线

`v0.25.1-alpha` 目标机人工审查证明，当前主入口仍走旧同步格式审查链，WPS 的纸张枚举、point 长度、行距模式和浮点值未经来源规范化便与 twip 模板值比较并直接展示，导致合规文档产生误报和不可理解的当前值。旧链虽然携带段落序号，但没有形成已验证锚点、章节路径或布局页码，因此把已有位置统一显示为位置待确认。

决定格式审查主入口停止使用旧同步结果链，统一进入确定性后台审查链，并以新的 `format_snapshot.v2` 契约承载带类型、单位、来源、原始值和规范值的格式事实。纸张枚举必须转换为语义纸型，point 长度必须确定性转换为 twip，行距必须结合行距模式区分多倍、固定值和最小值；混合、未知或宿主不支持的值不得参与合规判定。旧裸数值快照和报告不做猜测迁移，已有任务、缓存和结果失效后重新审查。

唯一活动规则包的中文显示名称为“技术文档模板规则”，稳定机器标识为 `technical-document-template-rules`，首个规则版本为 `1.0.0`，上游来源版本独立记录为 `wx-doc-format 0.12.15`。上游快照是候选规则源，规则逐条分为 `normative-format`、`normative-structure` 和 `converter-only`；模板资产提供明确格式值，只有人工准入的输入文档结构规则可以补充进入编译白名单，转换器成品合同、写回行为和代码 fallback 不得成为审查标准。模板没有定义的属性保持未配置，不能由 fallback 静默补齐。

“技术文档模板规则”首版不把纸张类型和四边页边距作为合规规则，因此这些差异不产生格式问题；采集边界仍须规范化并回归纸张枚举和页边距单位，以保证诊断可信并防止同类换算错误污染缩进、段间距和行距。旧模板和规则资产移入历史区域并标记为不活动，从运行时注册、交付白名单和用户界面移除，不允许自动回退，但保留 Git 历史和审计可追溯性。

格式问题继续以已验证原文锚点作为稳定身份。段落级问题显示章节路径、段落序号和原文摘要，并在 WPS 能验证布局时附加审查快照页码；节级问题显示节或章节及可用页码范围，文档级问题显示全文。快照页码不是稳定锚点，文档变化或宿主无法验证时可以省略，但不得在仍有已验证章节或段落位置时统一显示位置未确认。

格式审查界面、Markdown 报告和复制文本只显示中文可读值；规则键、枚举码、原始浮点值、英文字段和错误码留在可展开诊断或机器协议中。没有可靠中文映射时显示无法识别，不得猜测或直接暴露原始字符。API JSON、任务快照和诊断包继续使用稳定机器字段和值协议，不把中文文案写入机器契约。

项目负责人确认作者已经授权 AI-WPS 全量使用本地 `wx-doc-format` 源码、模板资产和规则，不要求附加授权证据，也不设置授权材料发布门禁。全量可使用只解除来源范围限制，不改变规则分类和人工准入要求。

本决策取代 ADR-0072 和 ADR-0115 中“上游模板值或规则不得成为格式标准权威源”的部分。算法与规则职责分离、构建期编译、规则来源和完整性哈希、运行时只读加载、模型不得修改格式标准等约束继续有效。现有未通过人工审查的 `v0.25.1-alpha` 构建标记为 `rejected`；修复后仍作为同一产品版本的新候选构建，以独立构建标识和日期区分，并保持 ADR-0118 确定的 Preview 版本边界。

D-0001 仍作为独立 DOCX 本地抽取缺陷修复：解析数字 `styleId`、安全读取样式关系并按已确认的 `outlineLvl` 边界回退，同时补齐恶意 DOCX 回归。该修复不混入 ADR-0116 的无行为变化共享抽取重构。
