# 本地文档抽取提升为三宿主共享能力

本地文档抽取与素材暂存原本只服务 PPT 文档总结，实现位于 `app/services/ppt/`。随着工作流平台因速度和 max token 限制预计被淘汰、后续新需求主要采用模型直连，本地文档抽取从 PPT 的局部优化变为素材类任务的唯一可行通路。因此将其提升为宿主无关的共享模块 `app/services/documents/`，Word 与 PPT 共同引用，不保留副本。

选择共享而非在 Word 下另建一套，是因为现有实现已经承载经过验收的安全资产：ZIP 条目与解压上限的恶意 DOCX 防护、`0700` 暂存目录、访问令牌校验、过期清理和重启后孤儿清理。复制一份会使这些约束出现两套实现，缺陷修复必须同步两处。

代价是 PPT 既有链路需要一次无行为变更的重构，且共享模块此后不能引入任何宿主特定假设。

## 已知缺陷

搬运前后均存在一个待修复缺陷：抽取器将 `w:pStyle/@w:val`（styleId）直接用于标题正则匹配，而未经 `word/styles.xml` 解析为样式名。在 styleId 为纯数字的文档中标题识别数为零。该缺陷不影响本 ADR 的决策方向，修复由后续独立变更承担，详见 `docs/known-defects.md`。
