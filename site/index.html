Phase 1 · Word / Excel / PPT

写在 WPS 里的内网 AI 助手

原生插件负责界面、读文档、预览和写回。规则、模板、配置、日志、诊断和模型调用留在本机 Adapter。当前范围是平台底座加三宿主，运行目标为麒麟 V10 ARM、Python 3.8、离线部署。

开始安装 查看 README

127.0.0.1 本机 Adapter，默认端口 18100
3.8 目标 Python，离线安装器

能做什么

模型结果先预览，确认后才写回。审查类和分析类任务默认只读。工作流平台走 /chat-messages，模型直连走 OpenAI 兼容 /chat/completions。运行时不回退统一 URL 或统一 Key。

Word

5 个入口

智能编写

改写、续写、提炼、自定义编写。预览 / 对照 / 纯文本后写回。

智能仿写

按模板仿写。预览、纯文本、复制，不写回。

文档审查

错别字、表达、逻辑、通畅性、专业性。选区或限量全文。

格式审查

对照《技术文件格式及书写要求》。格式问题卡片、题注关联结论、图像语义补充。不写回排版。

只读 · 视觉关闭可降级

写作规范

四个预置包 + 本机组织规范库。编写 / 仿写 / 审查可选用。

Excel

2 个入口

智能分析

选区或已用范围。结构化报告和汇报段落，不写回单元格。

只读

公式助手

明确选区，最多 30×20。生成或解释排错，只复制。

只复制

PPT

2 个入口

智能总结

当前页，或上传单个 .md / .docx（≤10 MB）生成整套页建议。只预览和复制。

只预览 / 复制

结构审查

最多 60 页。先判定幻灯片页角色，再执行规则豁免。只读。

只读

生产环境默认关闭模拟结果。图像语义补充默认开启；探针未过或总开关关闭时走视觉关闭降级，不得声称已看图。自动化门禁只得到 candidate，不能当成目标机已通过。

技术架构

三层各管各的。文档按结构化 payload 传递，健康状态决定能不能改配置、能不能发新任务。

  1. 01 WPS 用户

    在 Word / Excel / PPT 里点入口，不离开办公文档。

  2. 02 JS/HTML 插件

    界面、抽取、预览、写回。三宿主独立包，避免 Ribbon 串显示。

  3. 03 文档桥接

    段落、标题、字体、字号、对齐、大纲级别随 payload 走。

  4. 04 本机 Adapter

    127.0.0.1:18100。规则、模板、配置、日志、模型调用。

  5. 05 企业 AI 接口

    工作流平台或模型直连。密钥落在本机引用文件，不进配置正文。

预览后写回

Word 编写类任务先预览再确认。审查、分析、总结默认不改原文。

健康分四态

存活、就绪、增强降级、恢复模式。恢复模式禁止改配置和发新模型任务。

任务配置隔离

八类任务各自保存接入方式和密钥引用。运行时不回退统一地址。

安装方法

开发联调先起 Adapter、再装插件。内网目标机用离线交付包。覆盖安装保留已有配置、密钥、写作规范库和备份。

01

启动本地 Adapter

/health/live 不读业务数据。/health/ready 在恢复模式返回 503。缺 FastAPI 依赖时可 python adapter_service/standalone_adapter.py 18100。

cd adapter_service
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --host 127.0.0.1 --port 18100
02

构建或导入插件

产物在 wps-addon/dist/。正式终端优先导入 formal-plugin-kit/。

cd wps-addon
npm install
npm test
npm run build
03

配置企业 AI 接口

adapter.json 只保存接入方式、地址、模型参数和密钥引用。API Key 落在 run/provider_api_keys/<ref>。

cp config/adapter.example.json config/adapter.json
export ENTERPRISE_AI_API_KEY="your-api-key"
PHASE 1

一个三宿主包，一个安装脚本

默认产物 dist-offline/wps-ai-assistant-offline.tar.gz。系统 Python 无 pip 时，安装器对 get-pip 使用 -sS，不扫描麒麟 apt 的 dist-packages。

bash packaging/build_offline_bundle.sh
bash packaging/install.sh "$HOME/.wps-ai-assistant"
bash packaging/start_adapter.sh "$HOME/.wps-ai-assistant" 18100
bash packaging/diagnose.sh "$HOME/.wps-ai-assistant"
命令 用途
bash packaging/build_formal_plugin_kit.sh 正式插件手工导入包
bash packaging/build_probe_kit.sh 目标机探测包
bash packaging/build_adapter_start_kit.sh Adapter 手工启动包

给开发者

源码、测试和运维文档按目录分家。改代码前先读仓库手递。

仓库结构

  • wps-addon/插件源码（Vite + TypeScript）
  • adapter_service/本地 Adapter（FastAPI、规则、provider、测试）
  • formal-plugin-kit/正式 WPS 手工导入包
  • templates/办公模板和审校规则
  • packaging/离线安装、诊断、交付包构建
  • phase1-delivery-kit/一期安装器与验收材料
  • docs/设计、运维、验收说明

常用文档

模型配置 工作流 / 直连 写作规范 预置包与降级 智能编写 文档审查 格式审查 智能分析 结构审查 麒麟测试环境

测试：cd adapter_service && pytest；cd wps-addon && npm test。目标机回归用麒麟 V10 ARM64 上的 Python 3.8。后续可在同一 Adapter 上扩展多表 Excel、多文件对照、受控 PPT 生成和更完整的规范治理，不在当前 Phase 1 范围。
