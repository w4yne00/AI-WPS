# 01 — 文档审查接入共享任务协调器

**What to build:** 让 Word 文档审查成为共享长任务协调器的第一条完整链路。用户提交后能够看到排队、运行、完成或失败状态、真实阶段和耗时；排队任务可以取消，关闭并重新打开任务窗格后仍可查询同一任务。Adapter 重启后明确提示任务已中断，不伪装为可恢复。

**Blocked by:** None — can start immediately.

**Status:** ready-for-agent

- [ ] 文档审查通过共享协调器提交和查询，现有路由、结果结构、think 过滤、审查记录和只读行为保持不变。
- [ ] 默认并发 2、排队容量 8、FIFO 和 `clientJobId` 幂等在可控任务下可验证。
- [ ] 外部状态包含 queued、running、completed、failed、cancelled，以及排队位置、阶段、耗时和是否允许取消。
- [ ] 只有 queued 状态可取消；运行中不显示或接受虚假的模型取消。
- [ ] 提交时冻结输入、工作流和仅存在内存中的认证快照，后续配置切换不改变该任务。
- [ ] 运行中任务不因容量被淘汰；终态从完成时起保留 2 小时，最多保留 50 条。
- [ ] 认证信息不进入响应、日志、诊断或持久化存储，终态后释放。
- [ ] FastAPI 与 standalone 对提交、查询、取消和错误返回保持一致。
